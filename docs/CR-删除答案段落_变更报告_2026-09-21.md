## 七、🚨 部署前阻塞项：`cloudbaserc.json` 环境变量与生产不同步

**这是本次部署的硬阻塞，不解决会直接引发线上故障。**

`cloudbaserc.json` 当前记录的关键环境变量（**本地值**）：

```
"FRESHNESS_ENABLED":        "false",
"FRESHNESS_FACTUAL_ENABLED": "false",
"SEARCH_PROVIDER":           "agnes",     ← 生产实际为 qwen
"GEN_MODEL":                 "agnes",
"QWEN_SEARCH_MODEL":         "qwen3.8-max"
```

而根据项目记录，**生产实际状态**为：`SEARCH_PROVIDER=qwen`（2026-08-08 为修复"用户感知不能联网"专门切换）。

**风险**：执行 `tcb fn deploy chat --force` 会套用 `cloudbaserc.json` 的 `envVariables` →
**`SEARCH_PROVIDER` 被静默改回 `agnes`** → `agnes` 是纯 LLM 代理、**不返实时联网数据** →
**联网功能失效，用户将再次反馈"不能联网"** —— 即 2026-08-08 刚修复的缺陷复发。

### 处置方式

#### ✅ 推荐：改用 `tcb fn code update`（**只换代码包，不碰函数配置**）

`tcb fn deploy` 的官方说明确认它会套用配置：

> Auto reads cloudbaserc.json, applies envId and functions[].**timeout/memorySize/description/envVariables** config

且**没有跳过该行为的选项**。

但 CLI 另有一条独立命令专管代码：

```
tcb fn code update <name>
  --code-secret    代码保护
  --deployMode     cos | zip | image
  --dir            指定云函数文件夹路径
  --json
```

**其选项列表中不存在 `envVariables` / `timeout` / `memorySize`** → 仅替换代码包，函数配置（含环境变量）原样不动。
（配套：配置更新是另一条命令 `tcb config update fn`，二者职责分离。）

**执行步骤**：

```bash
cd D:/不知道是啥/教员/weapp

# 0) 登录（若未登录；扫码，非交互不可用）
tcb login

# 1) 部署前快照 —— 记录线上环境变量作为对照基准
tcb fn detail chat --json > chat-pre-deploy.json

# 2) 仅更新代码（注意：不是 tcb fn deploy）
tcb fn code update chat --dir cloudfunctions/chat --deployMode zip

# 3) 部署后对照 —— 环境变量必须与第 1 步快照逐项一致
tcb fn detail chat --json > chat-post-deploy.json
#   人工比对两份 JSON 中的 envVariables 字段
```

**⚠️ 注意**：`tcb fn code update` 是 **update** 语义，要求函数**已存在**（`chat` 已存在 ✅）。首次创建仍需 `tcb fn deploy`。

#### 备选方式（若 `tcb fn code update` 因权限/版本受限而不可用）

| 方式 | 说明 |
|---|---|
| **A. 同步配置** | 先把 `cloudbaserc.json` 的 `envVariables` 逐项核对为**线上实值**，再 `tcb fn deploy` |
| **B. 绕开 CLI** | 改用**微信开发者工具**上传部署云函数（不套用 `cloudbaserc.json`） |
| **C. 临时剥离** | 部署前临时移除 `cloudbaserc.json` 中的 `envVariables` 字段，部署后确认并恢复 |

（原推荐为 B。在确认 `tcb fn code update` 可用后，改为上面的推荐方式 —— 它同样规避静默覆盖，且留在命令行内可脚本化、可复核。）

**本次仅需更新云函数代码、不需要变更任何环境变量**，因此所有方案的正确性都取决于同一件事：**部署后必须验证 `SEARCH_PROVIDER` 仍为 `qwen`。**
