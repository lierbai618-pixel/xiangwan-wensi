# 多会话列表实现（Phase F 冻结期破例 · v0.9.2）

## 1. 背景与决策
- 用户反馈：聊天页"需要有历史对话记录以及新对话"。
- 排查：历史对话功能代码**完整存在**（`history` 云函数 + 前端 `loadHistory/appendHistory/clearHistory`），但之前各阶段部署清单只部署了 `chat`/`admin`/`feedback`，**漏部署 `login` 与 `history` 两个云函数**，导致 `openid` 为空 + `history` 调用失败，历史从不显示。
- 用户选择：多会话列表（ChatGPT 式：保留多个历史会话 + 新建对话 + 切换），即新功能。
- **破例授权**：用户明确授权在 Phase F 冻结期实现该新功能（AskUserQuestion 确认）。
- **冻结纪律保持**：
  - `rag.js` 完全未动；回答结构 / 标签 / feedback 文案 / prompt 比例未改。
  - 仅新增**会话管理层**（history 多会话 + 前端会话列表/切换）。
  - `question_logs` 仅**新增** `conversationId` 字段（云库自动兼容；旧/无该字段数据仍计入百问聚合，可比性保持）。

## 2. 设计
### 2.1 后端 history 云函数（多会话模型）
- 集合 `conversations`：每条会话一个文档，其 `_id` 即 `conversationId`。
- 动作：
  - `list` —— 列出该 openid 全部会话（按 `updateTime` 倒序），返回 `[_id, title, updateTime, count]`。
  - `create` —— 新建会话，返回新会话 `_id`。
  - `load` —— 按 `conversationId` 加载该会话 messages（校验归属）。
  - `append` —— 追加一轮 `[user, assistant]` 到该会话；首条 user 消息前 20 字自动作会话标题。
  - `remove` —— 删除指定会话（校验归属）。
- 所有按 `conversationId` 的读写均校验 `doc.openid === OPENID`，越权返回错误，避免串号。
- 因 `history` 从未部署过，`conversations` 集合无旧数据，直接新模型，无需迁移。

### 2.2 前端
- `app.js`：`login()` 注入 `openid`（之前漏部署导致为空，本次一并补部署）。
- `chat.js`：
  - `onShow` 校准备会话：`currentConversationId` 存在则 `loadConversation`，否则 `createConversation`（避免重复加载同一会话）。
  - `data._convId` 贯穿 load / append / 新对话。
  - `send` 拆出 `_doSend`，兜底逻辑：会话未就绪先建再发；`chat` 云函数调用与 `appendHistory` 均带 `conversationId`。
  - 顶栏「清空」→「新对话」（`newConversation` = 新建空白会话，旧会话保留在列表）；新增「会话」入口（`openSessions` → `navigateTo` sessions 页）。
- `sessions` 页（新增 `pages/sessions/`）：列出全部会话（标题 + 时间）、「+ 新对话」、点击进入（设 `currentConversationId` + `navigateBack`）、删除（remove + 若删当前则清 storage）。
- `app.json` 注册 `pages/sessions/sessions`（不入 tabBar，用 `navigateTo` 打开）。

### 2.3 数据闭环
- `chat/index.js`：`main` 透传 `event.conversationId` 给 `logQuestion`；`question_logs` 新增 `conversationId` 字段（可空，向后兼容）。
