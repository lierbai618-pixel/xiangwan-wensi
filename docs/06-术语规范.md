# 06 术语规范（Terminology）

> 统一全项目（Prompt / 前端 / 后端 / 数据库）的用词，避免同一概念多种叫法造成混淆。
> 任何新文档、新代码、新 UI 文案都应遵循本表。

## 核心术语

| 术语（English） | 中文 | 含义 | 禁用写法 |
|---|---|---|---|
| **Citation** | 引用 | 来自知识库的经典原文 + 出处（书名·篇目）。可溯源、不改写。 | 出处、Reference、引文（混用） |
| **Interpretation** | 解读 / AI 解读 | AI 对原文的分析，必须明确区别于 Citation，不得伪装成原文。 | 分析（与视角混淆时）、感悟、评注（无标注） |
| **Chunk** | 片段 | 知识库最小检索单元（由 ingest 切分生成）。 | 块、切片、段落（混用） |
| **Knowledge** | 知识 / 知识库 | 经来源登记、审核后入库的资料整体；或单条资料。 | 语料、资料库（无界定时） |
| **Perspective** | 思考框架 / 视角 | 分析问题的框架（综合 / 实践 / 儒家 / 道家 / 斯多葛 / 存在主义 / 心理学）。是工具，不是立场。 | 哲学视角（与流派混）、学派、阵营 |
| **Reflection** | 反思 / 回顾 | 用户在「思辨模式」中的回顾步骤，或用户的自我省思。 | 总结、复盘（无标注） |
| **Intent** | 意图 / 主题 | 系统识别到的问题主题（焦虑 / 成长 / 学习 / 关系 / 意义 / 选择）。 | 分类、标签（混用） |

## 使用约定

1. **Citation ≠ Interpretation**：任何展示引用原文的地方，必须能区分"这是原著"还是"这是 AI 说的"。前端用不同样式/区块；Prompt 用【经典原文】与【AI 解读】分段。
2. **Perspective 是分析工具**：切换"儒家视角/道家视角"= 换分析框架，不表示用户或产品"站队"。UI 文案避免"选择学派"。
3. **Chunk 只用于检索内部**：用户可见的是 Citation（引用），不是 Chunk ID。调试/遥测才暴露 Chunk ID。
4. **Knowledge 必须可审计**：每一 Knowledge 都对应 `knowledge/` 原始文件与来源登记（见 `03-知识库规范.md`）。

## 字段命名（数据库 / 接口）

| 概念 | 字段名（统一） |
|---|---|
| 引用原文 | `text`（chunk）/ `citation.display_text` |
| 引用出处 | `citation.source_position`（书名·篇目·起止） |
| 思考框架 | `perspective`（遥测）/ 前端参数 `framework` |
| 问题主题 | `intent`（遥测） |
| 命中片段 ID | `chunk_ids`（遥测） |
| 引用条数 | `citation_count`（遥测） |
| 安全触发 | `safety_triggered`（遥测） |
