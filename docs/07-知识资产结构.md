# 07 - 知识资产结构（Knowledge Asset Structure）

> 阶段：Phase C-1（设计）→ Phase C-2（接口+验证）→ Phase C-3（扩容与冻结，2026-07-26）
> 性质：**设计文档 + 接入规范 + 已验证**。Phase C-3 已将 10 本公版哲学经典完成资料包与本地入库验证，并冻结旧 corpus.json。
> 关联：`03-知识库规范.md`（来源登记/版权/Chunk 原则）、`04-技术架构.md`（Provider→Retriever→Citation→LLM）、`ingest/` 云函数。

---

## 1. 目的与范围

本文件定义「哲学思辨助手」**原始资料仓库**的结构与接入规范。目标不是一次建成百科，而是先把**知识资产结构**设计清楚，使未来能从「AI 聊天工具」升级为「真正可审计、可追溯、可扩展的知识系统」。

**Phase C-3 交付物（2026-07-26）**：

1. `knowledge/` 目录树（四类 + 模板 + 10 个 `ready` 资料包 + 3 个 `pending`）。
2. 每本书 `metadata.json` 规范（含 `perspective` / `themes` / `problem_tags` / `user_questions` / `scenarios` / `authority_level` / `citation`）。
3. 10 本公版哲学经典真实入库（本地验证）+ 召回测试集。
4. 旧 `corpus.json` 冻结至 `archive/corpus.legacy.v1.json`，并以非敏感哲学语料替身替换运行时 `corpus.json`。

**本阶段不做**：不引入 embedding / rerank / 多 Agent（按评审「不要急着做」）；不擅自变更产品定位；不把受版权保护或需时政资质的内容纳入知识库。

---

## 2. 仓库定位：`knowledge/` 与运行时数据分离

| 层 | 路径 | 内容 | 谁改 | 是否参与构建 |
|---|---|---|---|---|
| **原始资料仓** | `knowledge/` | 每本书 `metadata.json` + `source.txt/md` | 人工策展 | 否（仅被 ingest 读取） |
| **运行时集合** | 云数据库 `documents` / `chunks` / `citations` / `audit_log` | 解析后、切分后、带 `category/perspective/themes` 的记录 | `ingest` 写入 | 是 |

设计原则（来自 `决策原则.md` + 用户评审）：

- **资料来源与数据库始终分离**：`knowledge/` 是可审计的「素材库」，任何一段引用都能反查到源文件与章节。
- **旧内容冻结不删**：原 `corpus.json` 旧语料已在 Phase C-3 移入 `weapp/archive/corpus.legacy.v1.json`，不参与构建、不被引用、可回查。
- **只归档不删除**：任何资料下架 = 在 `knowledge/index.json` 标记 `status: archived`，不从磁盘抹除。

│   ├── metadata.json
│   └── source.example.md

│   ├── lunyu/  mengzi/  daxue/  zhongyong/  daodejing/  zhuangzi/

每本书一个文件夹，**文件夹名 = 稳定 slug**（英文小写 + 下划线），供 `ingest` 与 `index.json` 引用。

## 4. 单本书资料包结构

每本书目录下 **必须** 包含：

| 文件 | 作用 | 必填 |
|---|---|---|
| `metadata.json` | 结构化来源登记 + 分类 + 视角 + 主题 + 用户问法 + 引用模板 | ✅ |
| `source.txt` 或 `source.md` | 原文/校勘本正文，**用 `#` 表示章节** | ✅（入库前；`pending` 可暂缓） |

> `source` 用 Markdown 的 `#` 一级标题切分章节——与现有 `ingest` 的 Markdown 切分逻辑一致（按 `#` 分节，章节名写入 chunk 的 `section`），保证**章节结构不丢**。

## 5. `metadata.json` 字段规范

对齐 `03-知识库规范.md` 的来源登记字段，并新增 `perspective` / `themes`（C-2 注入 chunks）、`problem_tags` / `user_questions` / `scenarios` / `authority_level` / `citation`（C-3 升级，强化「现实问题→思想资源」桥梁）。

```json
{
  "id": "lunyu",
  "title": "论语",
  "author": "孔子（弟子及再传弟子编纂）",
  "translator": null,
  "source": "以杨伯峻《论语译注》作校勘参考（不整本入库）",
  "edition": "杨伯峻《论语译注》校勘参考",
  "publisher": null,
  "year": "先秦（约公元前5世纪）",
  "copyright_status": "public-domain",
  "license_note": "CC0 / 公有领域（原文）",
  "verification_date": "2026-07-26",
  "category": "中国哲学",
  "perspective": "儒家",
  "themes": ["修身", "学习", "为人", "成长"],
  "problem_tags": ["迷茫", "选择", "自我成长", "学习", "为人处世", "焦虑", "价值感", "意义", "成为更好的人", "自我提升", "完善自我"],
  "user_questions": [
    "年轻人迷茫的时候怎么办",
    "为什么知道道理却做不到",
    "如何成为更好的人",
    "不知道未来选什么方向很焦虑"
  ],
  "scenarios": ["青年成长", "人生选择", "学习焦虑", "自我认识"],
  "authority_level": 5,
  "citation": { "template": "《{title}·{section}》", "example": "《论语·学而》" },
  "language": "zh",
  "source_type": "ancient-text",
  "chapter_split": "by-book",
  "legalConfirm": true,
  "status": "ready",
  "notes": "章节用《学而》《为政》等篇名；引用位置以篇名+章节定位。"
}
```

| 字段 | 类型 | 说明 | 注入 chunks？ |
|---|---|---|---|
| `id` | string | slug，唯一 | document_id |
| `title` | string | 书名 | chunk.title |
| `author` | string | 作者 | chunk.author |
| `translator` | string? | **译本译者（公版译本需注明；作者版权结束≠译本版权结束）** | 冗余存储 |
| `source` | string | 校勘/底本/来源说明 | chunk.source |
| `edition` | string? | 版本说明 | 否 |
| `publisher` | string? | 出版方 | 否 |
| `year` | string | 年代 | chunk.year |
| `copyright_status` | enum | `public-domain` / `public-domain-translation` / `authorized` / `protected` / `pending` | 审计 + 闸门 |
| `license_note` | string | 授权说明 | 审计 |
| `verification_date` | string | 来源核验日期（YYYY-MM-DD） | 审计 |
| `category` | enum | 中国哲学/西方哲学/心理学/文学 | chunk.category |
| `perspective` | string | 学派视角（儒家/斯多葛/存在主义…） | **chunk.perspective（C-2 新增）** |
| `themes` | string[] | **思想主题**（修身/学习/情绪…） | **chunk.themes（C-2 新增）** |
| `problem_tags` | string[] | **用户问题词汇**（迷茫/选择/成为更好的人…），与 themes 区分，是「用户问题→思想资源」的桥梁 | **chunk.problem_tags（C-2 新增）** |
| `user_questions` | string[] | **真实用户问法语料库**（年轻人迷茫时怎么办…）；未来比向量库更值钱，需持续策展 | 不参与切分，仅用于召回桥接与评测 |
| `scenarios` | string[] | **适用场景**（青年成长/人生选择/组织管理…），用于跨书场景检索 | 不参与切分，仅用于召回桥接 |
| `authority_level` | int 1~5 | **权威等级**（5=原著正文，4=正式讲话，3=研究，2=二手解释，1=网络资料）；回答时优先引高等级 | 冗余存储，回答层可据此排序 |
| `citation` | object | **引用模板**（template/example），前端据此渲染引用卡片 | 不产生数据，仅约定格式 |
| `language` | enum | zh / en | 否 |
| `source_type` | enum | ancient-text / translation / excerpt | 否 |
| `chapter_split` | enum | by-book / by-chapter / by-section | 切分策略 |
| `legalConfirm` | bool | 来源合法性确认（一票否决闸门） | 写 documents.legalConfirm |
| `status` | enum | `pending` / `ready` / `archived` | manifest 用 |
| `notes` | string? | 策展备注 | 否 |

> **`themes` vs `problem_tags` vs `user_questions`**（关键区分，来自评审）：
> - `themes` = 思想主题（这本书讲什么：修身/情绪/行动）。
> - `problem_tags` = 用户问题**关键词**（迷茫/职业选择/成为更好的人）。
> - `user_questions` = 用户**真实问法**的完整句子语料库（"年轻人迷茫的时候怎么办"）。它是 `problem_tags` 的自然延伸，直接服务于"现实问题→思想资源"召回与未来评测，且**比单纯向量库更具长期价值**。
> - 三者需从**真实用户提问**持续策展补全。
>
> **版权闸门**：`copyright_status` 为 `pending` 或 `legalConfirm=false` 时，`ingest`/`ingest_package` 必须拒绝（与 `documents.legalConfirm` 一票否决呼应）。

## 7. 入库验收标准（每本资料必须过）

来自用户评审「建立入库验收」约束：

1. **来源明确**：`metadata.json` 含 `title/author/edition/license`，`copyright_status` 非 `pending`。
2. **作者明确**：`author` 非空，古代集体编纂须注明。
3. **分类明确**：`category` ∈ {中国哲学, 西方哲学, 心理学, 文学}，`perspective` 非空。
4. **章节保留**：`source` 用 `#` 标题分章；`ingest` 产出 chunk 的 `section` = 章节名，不跨章切分。
5. **引用位置可追踪**：chunk 携带 `source_position`（字符区间），`citation.display_text` 能反查到「书名·篇名 [起-止]」。

附加（来自 `03-知识库规范.md`）：

6. **不修改原文**：`source` 为校勘原文，AI 解读在回答层生成，不混入资料。
7. **可追溯**：`knowledge/index.json` 记录每本 `status`，任何下架 = `archived`，不物理删除。
8. **问题资产齐备**（C-3 新增）：每本至少有 `problem_tags` 与若干 `user_questions`；核心书建议 ≥50 `problem_tags`、每主题 ≥10 真实问法（MVP 先用代表性子集，后续从真实提问持续扩充）。

## 8. 章节保留与引用位置规范

- **章节结构**：`source.md` 每篇/章以 `# 篇名` 起头；`ingest` 按 `#` 分节，节名写入 chunk.`section`。
- **引用格式**（回答层，见 `02-AI回答规范.md`）：
  `《书名·篇名》……（原文）` → chunk.`citation.display_text` = `《论语·学而》[0-42]`。
- **可追踪链**：用户引用 → chunk._id → document_id → `knowledge/<category>/<slug>/source.txt#L<行>`。

## 9. Phase C-2 接口与检索桥梁（已实现，2026-07-26 验证）

`ingest` 云函数已扩展（向后兼容，不破坏现有 txt/md 输入）：

- **A. 单文件直传**（现有）：`{action:"ingest", content, title, author, category, perspective?, themes?, problem_tags?, legalConfirm, ...}`。
- **B. 资料包入库**（C-2 新增）：`{action:"ingest_package", package:"chinese_philosophy/lunyu"}` 或内联 `{action:"ingest_package", content, title, ..., problem_tags}`。
  - 开发/测试：云函数读取 `knowledge/<pkg>/metadata.json` + `source.*`（纯 Node 可用 `buildPackageChunks` 验证）。
  - **生产部署注意**：云函数包不含 `knowledge/`，故生产应由调用方（admin 页/构建脚本）读取资料包后以**内联 content+meta** 传入。
- 版权闸门 `checkIngestGate(meta)`：拒绝 `legalConfirm=false` 或 `copyright_status=pending`。
- `chunks` 集合已新增字段：`perspective` (string)、`themes` (string[])、`problem_tags` (string[])，由 metadata 注入。

**KB 检索桥梁（已实现）**：`rag.js` 的 `chunkSearchText` / `kbLexicalScore` 已把 `themes` + `problem_tags` 并入词法打分（纯词法增强，**未引入 embedding/rerank**）。检索路径：

```
用户问题 → tokenize → 与 chunk 的 themes/problem_tags 子串匹配（高权重）+ 原文 TF 余弦
         → 召回《书名·章节》chunk → shapeFromChunk 生成 citation（display_text + source_position）
```

> 验证：`scripts/test_c2_ingest.js` 22/22 通过（C-2）；`scripts/test_c3_knowledge_graph.js` 覆盖 10 本扩容后召回（C-3）。

## 10. 风险与版权闸门

- **版权是第一闸门**：`copyright: pending` 或 `legalConfirm: false` 的资料，`ingest` 必须拒绝。
- **译本陷阱**：现代作品（小王子/悉达多）作者过保护期 ≠ 译本公版；入库须用明确公版译本并注明译者。
- **心理学作品**：弗兰克尔等现代作品受版权保护，MVP 不整本入库。
- **内容无关**：本结构是通用知识生产线，资料均为哲学/文学/心理学公开经典；原敏感语料已冻结至 `archive/`，不参与任何构建。
