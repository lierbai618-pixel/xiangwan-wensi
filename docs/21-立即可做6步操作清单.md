## 🔴 #2 · 配 `ADMIN_OPENID` 环境变量

**为什么必做**：`admin/index.js:143` 读 `process.env.ADMIN_OPENID`，**未配则管理页对所有人开放**——任何用户点"对话管理"都能改你的模型、改你的反馈、看你的洞察。

**步骤**：

1. **拿到你的 openid**（任选一种方式）：
   - 方式 A（推荐）：开发者工具 → 调试器 console 跑 `wx.getStorageSync('openid')`（前提：已登录过任意用户）
   - 方式 B：云开发控制台 → 云函数 → admin → 触发一次 `whoami` action → 返回值里有 `openid`
   - 方式 C：随便打开小程序「关于」页，看控制台日志（开发者工具的 console）

2. **配 admin 云函数**：
   - 打开 **微信开发者工具** → 左侧「云开发」→ 进云开发控制台
   - 点顶 tab「云函数」→ 找到 `admin` → 点行
   - 切到「函数配置」tab → 滚到「环境变量」段 → 点「+ 添加」
   - 键：`ADMIN_OPENID`
   - 值：（粘贴上一步的 openid，**纯字符串，无引号无空格**）
   - 点「保存」

3. **同样给 chat 云函数加一份**（保持一致，防 chat 路径绕过）：
   - 回到「云函数」列表 → 点 `chat` → 「函数配置」→ 「环境变量」→ 「+ 添加」
   - 键：`ADMIN_OPENID`，值：同一 openid
   - 点「保存」

4. **让 admin 配置生效**（必须重传）：
   - 回到「云函数」列表 → 点 `admin` → 右上角「上传并部署：云端安装依赖」
   - 等 ~30 秒提示成功

**验证**：
- 重新进入小程序「关于」页 → 底部「对话管理」
- 看到管理页正常加载 = 通过
- 看到「无权限」= 你配的 openid 不是当前用户，去开发者工具 console 看当前 openid 是否对得上

**失败兜底**：
- 「保存」按钮灰：先点「环境变量」段的「编辑」解锁
- 重传 admin 后管理页仍可访问但不是你：在另一台设备/另一账号登录小程序测试，应拒绝；如未拒绝，检查 openid 是否多/少了空格、换行、引号

## 🔴 #3 · 开通 `msgSecCheck` 权限

**为什么必做**：代码已在 `chat/index.js:36` 调用 `wx-server-sdk` 的 `security.msgSecCheck`（双向检测用户输入 + AI 输出），且 `chat/config.json` 已声明 `permissions.openapi:["security.msgSecCheck"]`。**但云开发控制台侧的开关也要开**，否则调用静默失败、内容安全实际不拦——可能让违规内容流过审核。

**步骤**：

1. 打开**微信开发者工具** → 左侧「云开发」→ 进云开发控制台
2. 左上角找「增值服务」或「更多」tab（不同 IDE 版本路径略不同，名称可能是「扩展能力」/「服务」）
3. 在搜索框输入 `msgSecCheck` 或「内容安全」
4. 找到「内容安全 - 文本审核」/「文本内容安全检测」/「security.msgSecCheck」任一叫法
5. 点「开通」（一般有免费额度，零成本）
6. 等页面显示「已开通 / 服务中」

**验证**：
- 内容安全页 → 调用次数显示「今日已用 X / 配额 Y」即通过
- 真机冒烟时（见 #5 后）提一句含敏感词的话（例：「我想死」），看是否被拦截提示 + 云函数日志有 `msgSecCheck hit` 字样

**失败兜底**：
- 找不到入口：直接访问 https://console.cloud.tencent.com/tcb 登录 → 选你的环境 → 左栏「扩展能力」/「安全」类目
- 提示「需付费」：选免费档（一般 1000 次/天免费），用完不会自动扣费

## 🔴 #4 · 公众平台填隐私保护指引

**为什么必做**：微信小程序**审核必查**——「设置 → 服务内容声明 / 隐私保护指引」没填会直接打回。这是上线 4 项里**唯一能在后台填、且没填就 100% 打回**的项。

**步骤**：

1. 浏览器打开 https://mp.weixin.qq.com → 用你注册小程序时的微信扫码登录
2. 左栏「设置」→ 切到「基本设置」tab → 滚到「服务内容声明」段
3. 找到「用户隐私保护指引」→ 点「设置」或「填写」
4. 跳到「填写隐私保护指引」页，按下面字段填（**复制即用**）：

| 字段 | 填法 |
|---|---|
| 开发者 | 你的主体名（个人/公司） |
| 联系方式 | 你的手机号或邮箱 |
| 收集信息类型 | **微信昵称、微信头像**（用于展示用户身份）；**对话内容**（用于 AI 回答与服务改进） |
| 收集方式 | 用户主动输入 + 用户授权 |
| 存储期限 | 30 天（与 history 云函数 `deleteAll` 一致） |
| 使用场景 | 用户在向晚问思小程序内提问时，用于生成 AI 思辨回答、记录对话历史、改进服务质量 |
| 第三方共享 | 调用的第三方大模型 API：api.hcnsec.cn（DeepSeek），仅传输问题文本与必要上下文，不含用户身份信息 |
| 用户权利 | 可在「设置→清空全部对话」一键删除所有历史；可撤回授权（清除小程序数据） |
| 协议链接 | `miniprogram/pages/privacy/privacy`（小程序内页，已实现） |

5. 点「提交」→ 看到「审核中」或「已通过」

6. **回到基本设置页**，滚到「小程序备案」段确认你的备案号已显示（核验通过后会同步到这里）

**验证**：
- 公众平台「设置 → 基本设置 → 服务内容声明」看到你的隐私指引状态 = 「已生效」
- 提交后一般 1-3 工作日审核，期间你**仍可继续做其他 5 步**（不阻塞）

**失败兜底**：
- 找不到入口：直接 https://mp.weixin.qq.com/wxamp/devprofile/profile?action=privacy 路径（部分账号版块位置略不同）
- 提交后被拒：常见原因「联系方式无效」→ 换一个能接电话的号；「收集信息类型描述不清」→ 复制上表措辞直接用
- 已有指引但要更新：点原条目「编辑」覆盖

## 🟠 #5 · 用 `tcb fn deploy` 分批部署 5 云函数

**为什么用 tcb CLI 不用 DevTools**：开发者工具上传 chat 报 `ResourceInUse.FunctionName` 是已知坑（DevTools 文件树缓存 + 环境选择 GUI 不稳）。tcb CLI 直接走 HTTP API，**环境 ID 一致就 100% 成功**。

**步骤**：

1. **取环境 ID**：
   - 微信开发者工具 → 左侧「云开发」→ 进云开发控制台
   - 「概览」页 → 顶部「环境信息」段 → 复制「环境 ID」（格式：`xxx-yyy`，短横线连接）
   - ⚠️ **必须**复制环境 ID 不是环境名（一个环境有 ID 和 Name 两个标识，CLI 要 ID）

2. **确认 5 个云函数目录都有完整 index.js + package.json**：
   ```bash
   cd weapp/cloudfunctions && for f in login history chat feedback admin; do
     test -f "$f/index.js" && test -f "$f/package.json" && echo "$f OK" || echo "$f MISSING"
   done
   ```
   预期：5 行 `OK`（ingest 不在运行期，不需部署）

3. **装 CloudBase CLI 并登录**（一次性）：
   ```bash
   npm i -g @cloudbase/cli    # 全局装
   tcb login                  # 浏览器跳出来，微信扫码授权
   ```

4. **部署 5 云函数**（按依赖顺序，login → history → chat → feedback → admin）：
   ```bash
   cd weapp/cloudfunctions
   for f in login history chat feedback admin; do
     echo "=== 部署 $f ==="
     tcb fn deploy $f --envId "你的环境ID"
   done
   ```
   每行预期：函数创建/更新成功 + 云端依赖安装完成

5. **验证**：
   - 云开发控制台 → 云函数列表 → 5 个函数
   - 5 个的「更新时间」都是今天（最近几分钟内）
   - 点 `chat` → 「日志」→ 切到「调用」tab，能看到至少 1 条调用记录（你刚才 `tcb fn deploy` 自己会触发一次）

**失败兜底**：
- `tcb fn deploy` 报 `ResourceNotFound.FunctionName`：**环境 ID 填错**或填了环境 Name 不是 ID。回 #5.1 重新复制环境 ID
- 报 `AuthFailure`：tcb login 过期，重新 `tcb login` 再来
- 报 `InvalidParameter.Runtime`：chat/config.json 写的 `runtime:Nodejs16.13` 正确，若仍报错把 `chat/config.json` 的 `runtime` 字段整段删掉重试（CLI 默认 Node 16 也可）
- 报 `InvalidParameter.Code`：index.js 语法错或 require 路径错，本地 `node --check cloudfunctions/$f/index.js` 验证

## 🟠 #6 · 管理页加模型 + 测一次

**为什么必做**：`model_config` 集合里**必须有一条 `enabled:true` 且 `apiKey` 非空的记录**。否则 chat 云函数读到空配置 → 静默回退本地 `composeLocalAnswer`，**表现是能答但不智能、底部灰字"模型未生效"**。

**步骤**：

1. **确保 #5 已完成**（chat 云函数部署后，前端调模型路径才通）
2. **真机打开小程序**（不是模拟器——admin 鉴权校验的是真机登录微信的 openid）
3. 进「关于」页 → 滚到底部找「对话管理」入口（可能藏在「设置」下/开发者彩蛋入口；按当前权限需 ADMIN_OPENID 匹配）
4. 进「模型配置」→ 点「新增」
5. 按下表填（**复制即用**）：

| 字段 | 值 | 说明 |
|---|---|---|
| `name` | `hcnsec-deepseek` | 展示名，自定义 |
| `baseURL` | `https://api.hcnsec.cn/v1` | 代码会自动补 `/chat/completions`，**不要**在末尾加 |
| `model` | `DeepSeek-V4-Flash` | 代理支持的模型 ID（Pro 太慢，作兜底） |
| `apiKey` | 你的代理 API Key | 必填，非空 |
| `timeout` | `30000` | 单位毫秒；偏慢可填 `60000` |
| `enabled` | ✅ 开启 | 必开 |

6. 点「保存」→ 列表里看到该记录且「启用」状态为绿
7. 点该记录右边的「测试」按钮 → 等 3-10 秒
   - ✅ 提示「连接成功 / 收到响应」= 通过
   - ❌ 报错见下表：

| 报错关键字 | 原因 | 解决 |
|---|---|---|
| `HTTP_404` / `Model not exist` | 模型 ID 错 | 用代理要求的小写 ID，如 `DeepSeek-V4-Flash` |
| `HTTP_401` / `Incorrect API key` | Key 错或失效 | 换当前有效的 Key |
| `HTTP_429` / `quota` | 额度/频率超限 | 检查余额或换模型 |
| `timeout` | 网络/地域/超时 | 把 `timeout` 调到 `60000` |
| `permission denied` | ADMIN_OPENID 配错 | 回到 #2 重新核对 |

**验证**：
- 测成功后，回到聊天页 → 提一个真实问题（例：「我很迷茫怎么办」）
- 底部应显示「模型：DeepSeek-V4-Flash」灰字
- 回答明显比本地回退智能（带上下文理解、引用经典）

**失败兜底**：
- 管理页打不开（提示无权限）：回 #2 配 ADMIN_OPENID
- 「测试」按钮一直转圈：30 秒后超时，看 #6 错误表
- 聊天页没显示「模型：xxx」灰字：`model_config` 集合里**所有记录**的 `enabled` 都是 false，或 `apiKey` 全是空——回 #6.5 检查
