## 1. 背景与问题定义

### 1.1 触发事件

典型失败案例：

```
用户：房主任是谁
系统：RAG 未召回可靠知识，但仍生成了一个未经证实的答案。
```

这不是一次偶发的模型抽风，而是**架构缺陷的必然产物**。它与 Phase R 修复的"现在几点被误送 RAG 并自曝无法联网"属于同一类根因的两种表现：**系统把所有问题都塞进唯一的一条知识通路，于是通路必须为它不该回答的问题负责。**

### 1.2 三类事实的本质区别

WenDao 面对的用户问题，按"事实的存放位置"可以严格三分。这是整个 Phase S 的公理基础。

| 类别 | 定义 | 事实来源 | 时效 | 典型问句 | 归属层 |
|---|---|---|---|---|---|
| **运行时确定事实** | 由本机/运行环境即可确定，无需外部知识 | 系统时钟、计算器、设备上下文 | 秒级 | 现在几点、365×24、今天几号 | Capability（Phase R，已上线准备完成） |
| **外部世界事实** | 存在于系统之外、随世界变化、不可预先编纂 | 互联网公开信息 | 小时～年 | 房主任是谁、某公司怎么样、最近发生了什么 | **Search（本阶段设计）** |
| **长期稳定知识** | 已被人类沉淀、经过筛选、不随时间改变 | `corpus.json` + RAG | 千年级 | 孔子的仁是什么、道德经讲什么、依恋理论 | Knowledge（现役） |

三者的差异不在"难不难答"，而在**验证方式不同**：运行时事实靠**计算**验证，外部事实靠**引用**验证，长期知识靠**语料**验证。用同一套 RAG 去应对三种验证方式，必然在其中两种上失效。

### 1.3 为什么 RAG 结构性地不能解决"房主任是谁"

必须说清楚：**这不是语料不够多的问题，加语料永远解决不了它。**

**（1）RAG 是闭世界检索器，而问题是开世界的。**
`corpus.json` 是一个被策展的、有限的、静态的集合。它对"世界上存在但不在集合里的实体"没有任何表示。无论怎么扩充，明天出现的新人物、新事件、新产品都不在里面。这是集合论层面的缺口，不是工程层面的缺口。

**（2）向量检索没有"空集"语义。**
余弦相似度永远会返回一个 top-k。「房主任是谁」的向量不会返回"无"，它会返回语料中与"人物/称谓/身份/关系"最接近的几段——可能是《论语》里谈"知人"的段落，也可能是心理学里的角色理论。**检索器给出的是"最近邻"，而生成器把它读成了"依据"。** 幻觉就诞生在这个语义错位里。

**（3）置信度只被当作排序信号，没有被当作控制信号。**
现有链路中，相似度用于排名，但没有一个环节有权说"这个分数太低，不许回答"。缺少一个**否决权持有者**。

**（4）唯一可走的路是"生成"。**
系统面对未知实体时只有两个动作可选：生成，或者沉默。由于产品人格鼓励"给出有洞见的回答"，模型在两者之间必然选择生成。**人格设定在无外部证据通路时，会主动放大幻觉压力。**

**（5）缺少"我可以去查"的通路。**
Capability 解决了"我可以去算/去读时钟"，Knowledge 解决了"我可以去翻书"，但系统从未拥有"我可以去看看外面的世界"。Phase S 就是补这条通路。

### 1.4 一个必须提前说清的架构判断

> **搜索本身不消除幻觉。搜索只扩大"可回答集合"；真正消除幻觉的是 Evidence Gate，它定义"必须拒答集合"。**

如果只上 Search 而不上 Gate，结果是幻觉从"凭空编造"退化为"基于三条低质搜索结果编造"——看起来更可信，实际更危险，且更难被观测发现。因此本设计中，**Evidence Gate 不是 Search 的附属特性，而是与 Search 同等级的一等公民**（见第 7 章、第 10 章 S1/S2 关系约束）。

### 2.2 逐层职责契约

| 层 | 唯一职责 | 绝不做 | 失败时行为 |
|---|---|---|---|
| **Intent Router** | 决定"这个问题该由谁回答" | 不生成任何内容；不调用 LLM 做路由决策 | 无法判定 → 落到 Knowledge（保守默认，与现状一致） |
| **Capability** | 用运行时工具产生确定事实 | 不查外网；不读 corpus | 工具失败 → 明确说明能力边界，不猜 |
| **Search（新）** | 从互联网获取外部事实证据 | **不写 corpus、不 embedding、不参与向量检索、不替代 RAG** | 空/超时/错误 → 交给 Gate，输出 EMPTY，**绝不填补** |
| **Freshness（Q）** | 判断内容的时效敏感度并降权 | 不产生事实断言；不作为独立检索通路 | 关闭态 = 行为零变化（当前默认关） |
| **Knowledge** | 长期稳定知识的检索与阐释 | 不承担外部事实；不为未召回内容兜底生成 | 低置信 → 触发回流边，或交给 Gate |
| **Evidence Gate（新）** | 决定"允许回答什么" + 决定 answer_mode | 不检索、不生成 | 判据不足 → 强制 Honest Boundary |
| **Answer Composer** | 在 Gate 授权范围内组织语言与人格 | 不新增事实；不自选模式 | — |

### 2.3 关于层序的三个架构决策（重要）

**决策 A：Capability 优先级最高，位置不变。**
Phase R 已确立"运行时事实绕过一切检索"。「现在几点」不得进入 Search（多花一次网络往返、增加成本、且答案更差）。Phase S 接入点在 **Capability 之后**。

**决策 B：Search 在 Freshness 之前，且 Freshness 必须保持关闭直到 S 落地。**
Phase Q 的 Freshness Layer 与 Search Layer 存在**职责重叠区**——两者都关心"新的、外部的、时效性的东西"。若两者同时启用且都试图独立提供事实，会出现**双事实源冲突**，这是最难排查的一类缺陷。

> **架构裁决**：Search Layer 成为系统**唯一的外部事实出口**。Freshness Layer 长期应收敛为**信号产生者**（时效性标注 / 置信度降权 / 触发提示），而非事实提供者。在 Phase S 全量之前，`FRESHNESS_ENABLED` 必须保持 `false`。两者的最终合并列入 S4。

**决策 C：链路不是纯线性管道，存在一条回流边。**
Knowledge 低置信度 → 回流进 Search（Trigger C）。这意味着实现形态是**决策级联 + 一次受控回流**，不是四段流水线。回流最多发生一次（防止 Search→Knowledge→Search 震荡），且回流预算独立计费。

## 3. Search Router 设计

### 3.1 设计铁律

> **是否搜索，由确定性规则决定，不由 Prompt 决定。**

Router 的判定必须满足：可离线执行、可单测、可复现、可回归、可解释。任何"让模型自己判断要不要搜"的方案在本项目中被明确否决——它不可测、不可回滚、且会随模型版本漂移。这与 Phase R 的 `capabilities/router` 方法论完全一致（正则/词典 + 60→75 条离线用例）。

Router 输出为**判决对象**，不是布尔值：

```
RouteDecision {
  target        : CAPABILITY | SEARCH | KNOWLEDGE
  trigger       : A_EXPLICIT | B_UNKNOWN_ENTITY | C_LOW_CONFIDENCE | NONE
  entity_state  : KNOWN | UNKNOWN | NONE
  suppressed_by : <抑制规则ID> | null
  reason        : <可读判据串，用于观测>
}
```

### 3.2 Trigger A — 显式搜索请求（最高优先级，确定性最强）

用户已经明说要查外部信息。此时无需推断，直接放行。

**词面族（示意，非穷举）**

| 族 | 触发词 |
|---|---|
| 动作 | 搜索 / 搜一下 / 查一下 / 查查 / 帮我查 / 百度 / 谷歌 / 上网看看 |
| 时效 | 最新 / 最近 / 目前 / 现在的 / 今年 / 本月 / 刚刚 |
| 外部属性 | 官网 / 官方 / 新闻 / 报道 / 股价 / 价格 / 发布会 / 财报 |

**仲裁规则**
1. Trigger A 优先级 **高于** Freshness 的时效词命中（避免"最新"被两层争抢）。
2. Trigger A **低于** Capability。「现在几点」含"现在"，但 Capability 全串锚定优先（Phase R R-001 已加固的「北京时间」系列同理）。
3. Trigger A 命中但实体明显属于经典范畴（如「查一下论语里怎么说仁」）→ 判 KNOWLEDGE，理由记为 `A_overridden_by_corpus_entity`。这是必须处理的边界，否则搜索会侵蚀知识轨。

### 3.3 Trigger B — 未知实体检测（本阶段的核心创新）

这是解决「房主任是谁」的主判据。判定发生在 **RAG 之前**，成本极低。

**结构模式**：`[实体槽] + [事实型疑问框架]`

| 组件 | 内容 |
|---|---|
| 事实型疑问框架 | 是谁 / 是什么人 / 什么来头 / 干什么的 / 怎么样 / 靠谱吗 / 多少钱 / 在哪 / 什么时候成立 / 有什么产品 |
| 实体槽候选 | 非停用词的名词性片段；带称谓后缀（主任/总/教授/院士/董事长/老师+专名）；机构后缀（公司/集团/大学/研究院/平台）；产品/型号形态 |

**三态判决——关键在于实体要与语料对照**

引入 **Corpus Entity Registry（语料实体注册表）**：

- 由 `corpus.json` **只读派生**，构建期生成的检索用倒排/集合，**不回写、不修改源文件、不进入向量空间**。
- 内容：语料中出现的人名（孔子、老子、庄子、荣格、弗洛伊德…）、典籍名、核心概念词（仁、义、道、无为、依恋、投射…）。
- 用途：**只用于路由否决**，不用于回答。

判决表：

| 实体状态 | 含义 | 路由 |
|---|---|---|
| `KNOWN` | 实体命中注册表 | **KNOWLEDGE**（「孔子是谁」→ 走语料，不搜） |
| `UNKNOWN` | 存在实体槽但不在注册表 | **SEARCH**（「房主任是谁」→ 搜） |
| `NONE` | 未识别出实体槽 | 继续下游（不因 B 触发搜索） |

**这一张表是整个 Phase S 最重要的判据。** 它同时防住了两个方向的错误：不让搜索抢走经典问题，也不让 RAG 吞掉外部问题。

### 3.4 Trigger C — RAG 低置信度回流

**目标**：语料确实没有可靠召回时，自动进入 Search，而不是让 LLM 兜底生成。

**硬约束**：`rag.js` 被冻结，**不得修改**。因此置信度必须在**调用方侧**计算——这正是 Phase Q/R 已验证的"旁路包装"模式：编排层调用 rag.js，读取其返回值，在外部推导置信度，rag.js 本身零改动。

**代理置信度（Proxy Confidence）可用信号**（均取自 rag.js 现有返回与现有观测字段）：

| 信号 | 说明 | 现状可得性 |
|---|---|---|
| 召回条数 | 命中片段数量 | 待探针确认 |
| fallback 路径 | 现有观测已有 `classic-priority-domain` / `fallback-classic` / `cognitive-psych` | **已有**（N=37 快照中在用） |
| domain 判定 | 通用/情绪/人生/关系/事实/其他 | **已有** |
| intent 判定 | emotion/opinion/life/knowledge/growth | **已有** |
| top score | 相似度原始分 | **待探针确认（P-04）** |

> **架构诚实声明**：若探针确认 rag.js 当前返回不携带 score，则 Trigger C 在 S1 阶段**只能以粗粒度代理实现**（例如"命中 fallback-classic 且 domain=事实 且 intent=knowledge"），或者 **S1 只上 A+B，C 延后至 S3**。**不得为了 C 去解冻 rag.js**——除非单独走 ADR 审批。这个取舍必须在 S1 启动前定论，不能边做边定。

**Trigger C 的门禁（防止情感倾诉被送去搜索）**

C 仅在同时满足以下条件时才允许回流：
1. `intent ∈ {knowledge, opinion}` 且 `domain ∈ {事实, 通用}`；
2. `entity_state ≠ NONE`（有可搜的实体）；
3. 未命中抑制表；
4. 本会话回流预算未耗尽。

`intent ∈ {emotion, life, growth}` 的问题**永不触发搜索**。用户说「我最近很迷茫」，系统去搜索是产品事故，不是技术事故。

### 3.5 抑制表（Suppression List）——与触发同等重要

误触发的代价高于漏触发：漏触发退回今天的状态，误触发直接摧毁人格。因此抑制规则拥有**最终否决权**，位于所有 Trigger 之后执行。

| 抑制规则 | 示例 | 理由 |
|---|---|---|
| 自指人称 | 我是谁 / 你是谁 / 我该怎么办 | 内省与产品自述，绝不外搜 |
| 情绪表达 | 我好难过 / 撑不下去了 | 情感场景，搜索是伤害 |
| 假设与虚构 | 如果孔子活在今天 / 假设有一个人 | 无外部事实可查 |
| 纯哲学概念 | 什么是自由 / 意义是什么 | 语料轨 |
| 语料内实体 | 孔子 / 老子 / 荣格 / 仁 / 无为 | Registry 命中 |
| 隐喻式疑问 | 心里凉吗 / 你冷吗 | 呼应 Phase R 用 `.{0,2}` 紧间隔防隐喻误吃的经验 |
| 隐私敏感 | 含身份证/手机号/住址等模式 | **绝不外发第三方**（见第 11 章 S-R09） |

### 3.6 优先级总表

```
1. Capability（全串锚定优先）
2. 抑制表（一票否决，直接排除 SEARCH）
3. Trigger A 显式搜索  ─┐
4. Trigger B 未知实体   ├→ SEARCH
5. Freshness 信号（仅降权/标注，不改路由）
6. Knowledge（默认）
7. Trigger C 回流（Knowledge 之后，受门禁与预算约束，最多一次）
```

### 3.7 预算与冷却

| 项 | 默认建议 | 目的 |
|---|---|---|
| 单会话搜索次数上限 | 建议值待 S1 定标 | 成本与延迟护栏 |
| 单请求 provider 调用上限 | 1（主）+ 1（降级） | 延迟护栏 |
| 相同 normalized_query 缓存 | 短 TTL，独立命名空间 | 成本与稳定性 |
| 回流（C）每请求上限 | 1 | 防震荡 |

## 4. Search Layer 数据契约

契约的第一目标是**可追溯**：最终答案中的每一个事实断言，都必须能沿 `trace_id → SearchResponse → result.url` 反查到来源。做不到追溯的证据，视同没有证据。

### 4.1 SearchRequest（输入契约）

| 字段 | 含义 | 备注 |
|---|---|---|
| `trace_id` | 全链路追踪 ID | 贯穿 Router → Search → Gate → Answer → Log |
| `query_raw` | 原始用户输入 | **默认不落日志**（隐私，见第 9 章） |
| `query_normalized` | 归一化后查询 | 去噪、去语气词、繁简统一 |
| `query_rewritten[]` | 改写后的检索式 | S3 才启用；S1 恒等改写 |
| `trigger` | `A_EXPLICIT` / `B_UNKNOWN_ENTITY` / `C_LOW_CONFIDENCE` | 观测必备 |
| `intent` / `domain` | 沿用现有分类结果 | 复用现有能力，不新建分类器 |
| `entity_candidates[]` | Router 抽出的实体槽 | Gate 用它做覆盖度校验 |
| `freshness_need` | `none` / `recent` / `realtime` | 来自 Freshness 信号（只读消费） |
| `budget` | `{ timeout_ms, max_results, max_providers }` | 硬护栏 |
| `locale` | 语言与地区 | 影响 provider 选择 |
| `session_ref` | 会话引用（哈希） | **不含 openid 明文** |

**输入侧硬约束**：`query_raw` 在外发给任何 provider 之前，必须经过**敏感信息脱敏检查**；命中隐私模式则**不外发**，直接返回 `BLOCKED`。

### 4.2 SearchResponse（输出契约）

| 字段 | 含义 |
|---|---|
| `trace_id` | 与请求一致 |
| `provider_id` | 实际服务提供方标识 |
| `status` | `OK` / `EMPTY` / `TIMEOUT` / `ERROR` / `BLOCKED` / `QUOTA_EXCEEDED` |
| `results[]` | 结果数组，见下 |
| `unique_domain_count` | 去重后的独立域名数（Gate 主判据之一） |
| `entity_coverage` | 实体是否真实出现在结果中（0/1 或比例） |
| `normalized_confidence` | 归一化置信度（跨 provider 可比） |
| `latency_ms` / `cost_units` | 成本与性能 |
| `cache_hit` | 是否命中短期缓存 |
| `degraded` | 是否为降级路径产出 |

`results[i]` 结构：

| 字段 | 含义 |
|---|---|
| `rank` | 名次 |
| `title` / `snippet` | 标题与摘要（**仅使用 provider 返回的摘要，不抓取全文**） |
| `url` / `domain` | 出处，追溯锚点 |
| `source_tier` | `OFFICIAL` / `AUTHORITATIVE` / `GENERAL` / `UGC` / `UNKNOWN` |
| `published_at` / `retrieved_at` | 时效判据 |
| `provider_score` | 原始分（归一化前） |

### 4.3 数据生命周期与隔离硬约束

> 这一节是 Phase S 的**不可协商条款**。

| 约束 | 内容 |
|---|---|
| **禁止写入语料** | 搜索结果永不写入 `corpus.json`，永不追加、永不合并、永不"人工挑选后入库" |
| **禁止 embedding** | 搜索结果永不向量化，永不进入任何向量索引 |
| **禁止被 RAG 读取** | 缓存集合对 `rag.js` / `knowledgeRouter.js` 不可见，不建立任何引用关系 |
| **缓存物理隔离** | 若启用缓存，必须使用独立集合与独立命名空间，带强制 TTL，仅按 `query_normalized` 哈希键读写 |
| **仅存活于单次请求** | 搜索证据的默认生命周期是一次请求；缓存是性能优化，不是记忆 |
| **快照留存最小化** | 观测层只留 `domain` 与结构化指标，不留结果正文 |

**守门机制**：`corpus.json` 的 SHA256 在 Phase S 每个阶段的准入与准出都必须复核；出现任何漂移即判定为**架构违规**，直接回滚，不做例外讨论。

## 5. Provider 抽象设计

### 5.1 设计目标

不绑定任何具体搜索服务。Provider 是**可替换的外设**，不是架构组成部分。判断标准：换掉 Bing 换成 Tavily，Router / Gate / Composer / Observability 应当**零改动**。

### 5.2 SearchProvider 契约（能力描述，非实现）

每个 Provider 必须声明：

| 声明项 | 内容 |
|---|---|
| `id` | 唯一标识 |
| `capabilities` | 支持 web / news / 地区限定 / 时间过滤 / 是否返回 snippet / 是否返回 published_at |
| `limits` | QPS、单次最大结果数、最大查询长度 |
| `cost_model` | 计费单位与单价 |
| `latency_profile` | p50 / p95 参考值 |
| `compliance` | 服务归属地、是否可从微信云函数直连、数据出境属性 |
| `health` | 健康探测方式与熔断阈值 |

必须实现的语义动作（描述层）：**发起检索** / **健康探测** / **归一化输出** / **报告成本**。

### 5.3 三个必备组件

**（1）Provider Registry（注册表）**
配置驱动的 provider 清单，含 `primary` / `fallback` / `shadow`（影子调用，仅用于质量对比，结果不进入回答）。切换 provider 是配置行为，不是发版行为。

**（2）Normalizer（归一化层）**
把各家结构各异的返回统一为 §4.2 的 `results[]`。归一化必须包含：
- 排名 → 分数的单调映射；
- `source_tier` 判定（基于域名清单 + 规则）；
- 时间字段统一时区与格式；
- 缺字段的显式标注（缺 `published_at` 不等于"新"）。

**（3）Resilience（韧性策略）**

| 情形 | 行为 |
|---|---|
| 超时 | 立即返回 `TIMEOUT`，**等价于无证据**，绝不用"根据我的了解"补位 |
| 主 provider 失败 | 尝试 fallback（受 `max_providers` 约束） |
| 连续失败达阈值 | 熔断 N 分钟，期间直接走 Gate 的 EMPTY 路径 |
| 配额耗尽 | `QUOTA_EXCEEDED`，同样走 EMPTY 路径 |

> **韧性铁律**：**Provider 的失败必须表现为"我查不到"，而不是"我知道"。** 这是本项目所有降级路径的统一语义。

### 5.4 落地环境约束（微信云开发特有，必须写进选型 ADR）

| 约束 | 说明 |
|---|---|
| **搜索调用必须发生在云函数侧** | 小程序前端直连第三方搜索需加 request 域名白名单、且暴露密钥。云函数出网不受小程序白名单限制，且可保管密钥。**前端零搜索配置**，与"前端零模型配置"原则一致 |
| **Node 16.13 无可用原生 fetch** | 云函数运行时锁定 Nodejs16.13。HTTP 客户端方案必须在 S1 前明确，且**不得通过修改 `rag.js` 来复用其内置 nodeFetch** |
| **部署方式** | 沙箱不可达 SCF 代码上传端点，所有部署仍需人工在微信开发者工具执行"上传并部署·云端安装依赖" |
| **合规优先级** | 优先选择境内可直连、数据不出境、有正式商用条款的服务；小程序**备案审核中**，引入不可控外部内容需评估审核影响 |
| **密钥管理** | API Key 走云函数环境变量，不入库、不入前端、不入日志 |

## 6. 回答生成策略

### 6.1 四种回答模式

用户提出三种；**Evidence Gate 必然产生第四种**，它是本设计的反幻觉出口，必须显式建模。

| 模式 | 适用 | 结构 | 人格表达 |
|---|---|---|---|
| **Knowledge Answer** | 长期知识、哲学、心理学；语料高置信 | 现有五段式（理解→分析→行动→经典→思考） | **完全不变**，零回归 |
| **Search Answer** | 外部事实；证据充分 | 事实优先：结论 → 关键信息 → 出处 →（可选）一句思辨邀请 | 克制、可核查 |
| **Hybrid Answer** | 外部事实 + 可映射经典视角 | 分段隔离：【事实（带出处）】 →【思考（明确标为观点）】 | 先事实后思辨 |
| **Honest Boundary Answer** | 证据不足 / 空 / 冲突 / 被拦截 | 明确说明查不到 → 说明边界 → 可选下一步或转向 | **诚实即人格** |

### 6.2 模式选择矩阵

| 触发路径 | 语料置信 | 证据状态 | → 模式 |
|---|---|---|---|
| 无搜索 | 高 | — | Knowledge |
| 无搜索 | 低，但 intent=emotion/life | — | Knowledge（陪伴式，不宣称事实） |
| A / B / C | — | `SUFFICIENT` | Search |
| A / B / C | 中高（经典可映射） | `SUFFICIENT` | Hybrid |
| A / B / C | — | `WEAK` | Search（强不确定标注，禁止延伸） |
| A / B / C | — | `CONFLICTING` | Search（并列呈现分歧 + 各自出处） |
| A / B / C | — | `EMPTY` / `ERROR` / `BLOCKED` | **Honest Boundary（强制）** |

### 6.3 硬规则

1. **模式由 Gate 判定并下发，LLM 不得自选模式。**
2. **Search Answer 不得套用五段式。** 用户问「房主任是谁」，不需要"这让我们想到《论语》"。五段式是 Knowledge 轨的表达法，不是全局人格强制。
3. **Hybrid 模式下事实段与思辨段必须物理分段**，且经典引用**永远不能作为事实依据**——《论语》不能证明某个人是谁。
4. **任何模式下，未被证据支撑的具体事实（人名、职务、数字、时间、地点）一律不得出现。**

## 7. Evidence Gate 设计

Phase S 的价值中枢。它的存在目的只有一个：**让"不知道"成为一个系统级的、可强制执行的合法输出。**

### 7.1 双闸结构

**前置闸 · Admission Gate（生成之前）**
输入：`SearchResponse` + 语料置信 + intent/domain。
输出：`evidence_state` + `answer_mode` + **允许断言范围（allowed claim scope）**。
它决定"你可以说什么"，并把这个范围作为约束下发给生成环节。

**后置闸 · Assertion Gate（生成之后、出口之前）**
输入：候选答案文本 + 证据包。
动作：抽取答案中的事实性断言 → 与证据做实体级/字符串级对齐 → 未对齐的断言**剥离或整体降级**为 Honest Boundary。
它决定"你实际说了什么算不算数"。

> 只有前置闸是"相信模型会听话"；加上后置闸才是"不需要相信"。**架构不应建立在模型的服从性上。**

### 7.2 evidence_state 状态机

| 状态 | 判据（示意，阈值 S1 定标） | 允许输出 |
|---|---|---|
| `SUFFICIENT` | 独立域名数 ≥ 2 且实体覆盖命中 且无实质冲突 且时效满足需求 | Search / Hybrid |
| `WEAK` | 仅单一来源，或 tier 偏低，或时效存疑 | Search，**强制不确定标注**，禁止任何延伸推断 |
| `CONFLICTING` | 多来源对关键事实不一致 | Search，**并列呈现分歧**，不做裁决 |
| `EMPTY` | 无结果 / 结果与实体无关（覆盖度=0） | **Honest Boundary** |
| `ERROR` / `TIMEOUT` | Provider 异常 | **Honest Boundary** |
| `BLOCKED` | 隐私拦截 / 合规拦截 | **Honest Boundary（说明原因，不透露规则细节）** |

**特别强调 `EMPTY` 的一个隐蔽子情形**：搜索**返回了结果，但结果里根本没有这个实体**。这是搜索引擎的常见行为（返回近似词条）。若不做 `entity_coverage` 校验，这类结果会被当成证据，产生**比无搜索更危险的幻觉**——因为它带着 URL，看起来有据可查。**因此实体覆盖度校验是 Gate 的必备判据，不是可选优化。**

### 7.3 反幻觉硬规则（七条禁令）

在任何非 `SUFFICIENT` 状态下，以及所有状态的答案生成中：

1. 不得补全证据中未出现的人名、职务、头衔、单位。
2. 不得推断证据中未出现的数字、日期、金额、排名。
3. 不得由经典/理论推导出关于现实世界的事实断言。
4. 不得使用"据了解 / 一般来说 / 通常情况下 / 据说"等模糊语填补事实空缺。
5. 不得把 snippet 中的概括性表述**具体化**（"多年经验"→"20 年经验"是幻觉）。
6. 不得声称自己"记得""了解""知道"某个外部事实——只能说"检索到"或"没有检索到"。
7. `EMPTY` 状态下**不得输出任何具体事实**，哪怕是"可能是某单位的负责人"这类看似谨慎的推测。

### 7.4 验收案例走查

**S-CASE-01（主案例）「房主任是谁」**

```
Router  : Capability 未命中 → 抑制表未命中
          → Trigger B：实体槽「房主任」（称谓后缀）+ 疑问框架「是谁」
          → Registry 查询：不在语料实体表 → entity_state = UNKNOWN
          → target = SEARCH，trigger = B_UNKNOWN_ENTITY
Search  : 发起检索 → 假设 status=EMPTY 或 entity_coverage=0
Gate    : evidence_state = EMPTY → answer_mode = HONEST_BOUNDARY
Answer  : 「我没有检索到关于『房主任』的可靠公开信息。
           如果这是你身边的具体某个人，我这边查不到，也不想编一个答案给你。
           你要是愿意多说一点背景，我可以再帮你查；
           或者，你更想聊的其实是和这个人相处的那件事？」
出口     : 无事实断言 → 后置闸通过 → msgSecCheck → 返回
```

**S-CASE-02（抑制反例）「我是谁」** → 抑制表命中（自指人称）→ 绝不搜索 → Knowledge / 思辨轨。

**S-CASE-03（语料实体反例）「孔子是谁」** → Trigger B 结构命中，但 Registry 判定 `KNOWN` → **KNOWLEDGE**，不搜索。

**S-CASE-04（Capability 优先反例）「现在几点」** → Capability 全串锚定命中 → 不进入 Search（Phase R 行为零回归）。

这四个案例构成 Phase S 的**最小验收集**，其中 S-CASE-02/03/04 属于**误触发方向**，其通过率要求为 **100%**（沿用 Phase R "误判探测 0/18" 的验收方法论）。

## 8. 与 WenDao 人格融合

### 8.1 人格不变式

向晚问思的定位是**哲学思辨助手**，核心原则「先做人再引经」。Phase S 必须在获得外部感知能力的同时，不把产品变成"一个会搜索的聊天框"。

**不变式 1：五段式是 Knowledge 轨的表达法，不是全局强制。**
把五段式套到「房主任是谁」上，产生的不是人格，是滑稽。

**不变式 2：事实优先于思辨。**
用户问事实时，先给事实。思辨是**可选后缀**，不是前置仪式。

**不变式 3：「先做人」包含「不骗人」。**
承认不知道，不是人格的减损，恰恰是「先做人」最直接的体现。**Evidence Gate 不是套在人格外面的技术约束，它就是人格本身的一部分。** 这个论证必须写进产品语气规范——否则实现者会本能地觉得"拒答伤害体验"，从而在提示词里悄悄放水。

### 8.2 三条人格红线

| 红线 | 反例（禁止） |
|---|---|
| **不得为思辨而拖延事实** | 用户问是谁，先讲三段"我们为什么执着于身份" |
| **不得把"不知道"包装成禅意** | 「或许，答案不在外面，而在你心里」——这是用文学性掩盖信息缺失，是幻觉的另一种形态，**危害等同于编造** |
| **不得在事实段夹带价值判断** | 「这家公司成立于X年，看得出很有格局」——评价不是事实 |

### 8.3 语气契约

| 段落 | 语气 | 长度 |
|---|---|---|
| 事实段 | 克制、具体、可核查、带出处 | 按需 |
| 边界段 | 直接、不卑不亢、不道歉过度 | 1–2 句 |
| 思辨邀请（可选） | 温和、开放、与用户真实处境相关 | **≤ 1–2 句，且必须可省略** |

**思辨邀请的启用条件**：仅当问题本身带有价值/关系/处境色彩时才附加。纯事实查询（「某公司成立于哪一年」）不附加。**滥用思辨邀请会让它迅速变成噪音，比不加更伤人格。**

## 9. Observability 设计

### 9.1 设计原则

沿用 Phase P+ 已建立的观测体系（`observability_logs` 集合 + `KNOWLEDGE_OBSERVABILITY_STORE=cloud`）。**建议复用现有集合并新增 `search.*` 命名空间字段**，而不是新建集合——理由：现有 Dashboard / HealthScore 可直接扩展，避免多集合分裂导致的关联分析困难。

### 9.2 观测字段

| 字段 | 类型 | 说明 |
|---|---|---|
| `trace_id` | string | 全链路关联 |
| `layer_path` | string | 实际经过的层，如 `router>search>gate>answer` |
| `answer_mode` | enum | knowledge / search / hybrid / honest_boundary |
| `search_triggered` | bool | 是否触发搜索 |
| `search_trigger_type` | enum | A_EXPLICIT / B_UNKNOWN_ENTITY / C_LOW_CONFIDENCE / NONE |
| `entity_state` | enum | KNOWN / UNKNOWN / NONE |
| `suppression_hit` | string | 命中的抑制规则 ID（null 表示未命中） |
| `search_provider` | string | provider_id |
| `provider_status` | enum | OK / EMPTY / TIMEOUT / ERROR / BLOCKED / QUOTA_EXCEEDED |
| `source_count` | int | 结果条数 |
| `unique_domain_count` | int | 独立域名数 |
| `entity_coverage` | number | 实体覆盖度 |
| `evidence_state` | enum | SUFFICIENT / WEAK / CONFLICTING / EMPTY / ERROR / BLOCKED |
| `gate_decision` | enum | ALLOW / DOWNGRADE / REFUSE |
| `assertion_stripped` | int | 后置闸剥离的断言条数（**幻觉逃逸的核心指标**） |
| `confidence` | number | 归一化置信度 |
| `rag_confidence_proxy` | number/enum | 代理置信度 |
| `degraded` | bool | 是否降级路径 |
| `cache_hit` | bool | — |
| `latency_ms` | object | `{ router, search, gate, llm, total }` 分段计时 |
| `cost_units` | number | 本次搜索成本 |
| `error_code` | string | — |

### 9.3 隐私红线（必须严格执行）

| 禁止记录 | 替代方案 |
|---|---|
| 用户原始 query 全文 | `query_hash` + 长度 + intent/domain 标签 + 实体状态；原文默认**不落**，如需人工调优须显式开关 + 脱敏 + 明确保留期 |
| openid 明文 | 哈希后的 `session_ref` |
| 搜索结果正文 / snippet | 仅记录 `domain` 与结构化指标 |
| 位置、地址、联系方式 | **一律不落** |

> **必须引用的教训**：Phase R 上线前审查发现 **R-003**——位置授权分支的回答文本中含地址，会落入日志集合（目前因前端不传 location 而不可达，已列为 R2 硬性前置）。Search Layer 引入外部文本后，同类风险**从"潜伏"变为"高频"**：搜索结果里天然含大量人名、机构、地址。因此本层的日志策略必须是**默认不落文本、只落结构化指标**，而不是"落了再脱敏"。

### 9.4 三个必看指标

1. **触发精确率 / 召回率**：人工抽样标注，判断"该搜没搜"和"不该搜却搜了"。**误触发率的目标值是 0**。
2. **Gate EMPTY 率**：过高说明 provider 或 query 改写有问题；过低（接近 0）说明 Gate 可能形同虚设。
3. **幻觉逃逸率**：`assertion_stripped > 0` 的占比 + 人工抽检。这是 Phase S 唯一的终局指标。

**产出**
1. **rag.js 返回契约探针**（只读观察，零改动）：确认是否携带 score/命中数，决定 Trigger C 的可行形态。

3. **Mock Provider**：可离线复现 OK / EMPTY / TIMEOUT / CONFLICTING 各状态。
4. **Corpus Entity Registry 派生流程**（只读派生，源文件零改动）。

**准出门槛**
- 正例触发正确率 ≥ 95%
- **抑制集误触发 = 0（硬性，不接受任何非零）**
- 冻结资产 SHA256 零漂移

### S1 — 搜索能力接入

**范围**：Router（A + B，C 视探针结果决定）+ 单一 Provider + 数据契约 + 观测字段。
**开关**：`SEARCH_ENABLED` 默认 `false`；灰度顺序：内部账号 → 小流量 → 放开。
**约束**：
- Gate 必须在 S1 期间以**影子模式**运行（只判定、只记录 `gate_decision`，不改变输出），为 S2 提供定标数据。**不允许"S1 先上搜索、S2 再补 Gate"的裸奔窗口。**
- Provider 失败一律 EMPTY，S1 阶段 EMPTY 走**现有行为**（不新增回答模式），避免同时引入两处变化。

**回滚**：L1 = `SEARCH_ENABLED=false`（秒级熔断，免部署）；L0 = 单文件回退；L2 = 恢复基线。

### S2 — Evidence Gate

**范围**：前置闸 + 后置闸 + Honest Boundary + 四种回答模式 + 人格语气规范落地。
**准入**：S1 影子数据 ≥ 阈值样本量，且 Gate 判定分布合理。
**准出**：S-CASE-01～04 全通过；误触发 0；`assertion_stripped` 可观测。
**说明**：Gate **不设关闭开关**。关闭 Gate 等于恢复幻觉，不是一个合法的降级态。降级只能通过关闭 `SEARCH_ENABLED` 实现。

### S3 — 搜索质量优化

query 改写、source tier 域名分级、多 provider 与影子对比、缓存与成本优化、延迟优化（并行化、首字流式）、Trigger C 精化。
**准入**：S2 稳定运行且幻觉逃逸率达标。

### S4 — Freshness 收敛

将 Phase Q 的 Freshness 从"独立通路"降级为"信号产生者"，消除双事实源风险，确立 Search 为唯一外部事实出口。

### 阶段间硬性约束

> **Phase S 的任何实现阶段，不得与 Phase R 的观察期重叠。**
> Phase R 目前状态：代码就绪、Preflight READY、**但尚未真实部署**（待人工在微信开发者工具执行上传并部署 + 3 条首验 + 回填部署记录）。R 观察期要求 ≥50 真实样本方可准入 R2。在 R 完成部署验证前启动 S1，会导致两层变更混在同一批观测数据里，**任何异常都将无法归因**。这是 Release Guardian 的一票否决项。

## 附录 A · 一句话架构备忘

- **Capability 回答"我能算出来的"，Search 回答"我能查到的"，Knowledge 回答"人类沉淀下来的"，Gate 决定"我不该说的"。**
- **搜索扩大可答边界，Gate 划定拒答边界。只上前者会让幻觉更像真的。**
- **Provider 的失败必须表现为"我查不到"，而不是"我知道"。**
- **实时事实与外部事实永不进 `corpus.json`、永不 embedding、永不靠 Prompt 生成。**
- **承认不知道，是「先做人再引经」的第一句。**
