## 3. Prompt 变化

### 3.1 System 定位：从「经典解答机」→「会思考的通用助手」
- **旧**：你是「问道」，以经典哲学/文学/心理学帮助用户理解问题、形成判断；输出固定五段（理解→分析→行动→经典→思考）；经典是核心。
- **新**：你是「问道」，一个善于思考的 AI 助手。先直接、正常地回答用户的问题；**经典只是可选的论证依据，不是答题模板**。保留两条红线：① 危机干预最高优先级；② 只引用知识库真实内容，不得编造经典、不得误标出处。

### 3.2 输出格式：固定五段 → 动态四套
| 格式 | 触发 | 结构 |
|------|------|------|
| `technical` 直答式 | 技术/事实/危机（skip） | 直接回答，不分段、不引经、不哲学化 |
| `general` 通用式 | 普通生活/关系/观点 | 【回答】【分析】【建议】【延伸思考】 |
| `philosophy` 思辨式 | 哲学/人生/社会/道德/抽象追问 | 【理解】【分析】【经典观点(可选)】【思考】 |
| `emotion` 共情式 | 情绪支持 | 【理解】【分析】【建议】【思考】+ 先共情 |

### 3.3 RAG 角色：必引 → 可选论证依据
- `composeUserContent` 三种形态：
  - **skip**：明确「本轮未启用经典知识库，请直接、准确回答，不要引用经典，不要哲学化」；
  - **有资料**：「【可选参考资料】是论证依据不是答题模板……先独立完整回答，资料只在能真正支撑时才引用，不相关就完全不用，不得编造」；
  - **检索为空**：「知识库无相关内容，正常回答即可，不要编造任何经典引用」。
- 这一改动是「不强行经典引用」的前提——已用离线不变量校验（见 §5）。

### 3.4 多轮上下文
- 旧：6 条消息；新：`MAX_CONTEXT_ROUNDS = 10`（最近 20 条 user/assistant）。
- 追问经 `rewriteQuery` 重写为自足问题后再判定意图，使「那如何减少这种痛苦？」能正确落到上一轮话题。
- `history` 仅用于辅助情绪延续判定，**不参与领域判定**（避免历史话题污染当前问题）。

## 4. Intent 分类结果

`classifyIntent(query, history)` 输出 `{type, domain, knowledgePolicy, format, crisis, keywords}`。
判定优先级：**危机 > 硬事实域(skip) > 抽象追问(philosophy) > 情绪 > 观点 > 学习/成长 > 人生/社会/道德/关系/职业 > 事实句式 > 兜底观点**。

### 4.1 100 题单轮分布
| 维度 | 分布 |
|------|------|
| type | life 31 · emotion 26 · knowledge 21 · growth 17 · opinion 5 |
| knowledgePolicy | use 74 · skip 21 · optional 5 |
| format | general 31 · emotion 26 · philosophy 22 · technical 21 |

### 4.2 五类意图说明
| type | 含义 | 知识策略 | 格式 |
|------|------|----------|------|
| `knowledge` 知识咨询 | 编程/数学/科技/健康/事实等客观问题 | skip | technical |
| `life` 人生思考 | 人生/社会/道德/关系/职业/抽象追问 | use | philosophy/general |
| `emotion` 情绪支持 | 焦虑/崩溃/孤独等情绪倾诉 | use | emotion |
| `growth` 学习成长 | 学习/效率/习惯/自律 | use | general |
| `opinion` 观点讨论 | 「你怎么看…」且非人文域 | optional | general/philosophy |

### 4.3 边界处理（重点修复）
- **抽象追问 vs 个人倾诉**：`人为什么会痛苦` → `life/philosophy`（多角度分析）；`我很痛苦` → `emotion`（先共情）。靠 `ABSTRACT_ASK_RE`（人为什么/什么是/的本质…）无第一人称判定。
- **技术/事实误套经典**：`Python 的 list 和 tuple 有什么区别` → `knowledge/skip/technical`，**完全不检索、不引经**。
- **领域误判修复**：`机器学习` 曾因含「学习」误入学习域 → 重排 DOMAIN_RULES 使硬事实域（编程/科技）优先；`闭包/专注/忘/关系/压力/俱疲/不爱我` 等补入关键词。

## 5. 测试结果

### 5.1 离线 harness（`node tests/general-ai-test.js`）— 全绿
| 项目 | 结果 |
|------|------|
| 单轮意图分类（100 题） | **100 / 100 通过** |
| 多轮上下文承接（5 例） | **5 / 5 通过**（追问不丢话题、技术追问仍走 skip） |
| Prompt 装配不变量（8 项） | **8 / 8 通过** |

**8 项不变量**覆盖「不强行引用」前提：
- skip 类**不含**「可选参考资料」指令，且声明「不要引用经典 / 不哲学化」；
- use 类（空检索）声明「不要编造任何经典引用」；
- use 类（有资料）声明「论证依据」「不要为了引用而引用」；
- 危机类注入危机提示与热线 **12356**；
- 情绪类注入共情提示；
- 上下文窗口 **≤ 20 条**（10 轮）。

### 5.2 Phase F 回归（未破坏）— 全绿
- `node tests/rag-regression.js` → **通过**（社会专项全过、零 lex<2 违规召回）；
- `node tests/session-restore-sim.js` → **通过**（修复后回答完整恢复）。

### 5.3 需部署后验证的在线指标（架构已保证前提，但需实跑）
本 harness 保证的是「架构层不强制引用」与「意图/策略正确」。以下用户验收指标取决于模型实际生成，**须部署并用在线回归脚本验证**：
- 回答完成率 > 95%（模型可用、未全失败）；
- 错误引用数 = 0（依赖 §3.3 的「不得编造」约束 + 模型遵循度）；
- 多轮指代理解正确率（在线抽样）。
