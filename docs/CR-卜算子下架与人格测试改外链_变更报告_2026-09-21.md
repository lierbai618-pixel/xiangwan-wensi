## 三、第五轮：人格测试改为外部链接

### 3.1 🔴 为什么不是「跳转浏览器」

**微信小程序没有打开系统浏览器或外部 App 的 API。** 「跳转浏览器」在平台能力上**不存在**，必须换一种实现。四条路径对比：

| 方案 | 体验 | 合规风险 | 可行性 |
|---|---|---|---|
| **A. 二维码长按识别**（已采用） | 好 | ✅ 无（不触碰隐私接口） | ✅ 第三方域名可用 |
| B. `<text user-select>` 长按选中 | 一般（选中→复制→切浏览器→粘贴） | ✅ 无 | ✅ |
| C. `wx.setClipboardData` 一键复制 | 最好 | **🔴 有** | ✅ 技术可行 |
| D. `web-view` 内嵌 | — | — | **🔴 不可行**（需「业务域名」+ 域名归属验证，第三方站点过不了） |

**方案 C 被否决的原因**：`wx.setClipboardData` 属微信**隐私接口**。本项目当初**专门移除过剪贴板调用** —— `admin.js` 的 `copyOpenid` 从 `setClipboardData` 改为 `showModal`，目的即消除审核时的隐私接口拦截弹窗，并全仓 grep 确认零残留。**重新引入等于重新引入刚移除的审核风险**，且需先在《小程序用户隐私保护指引》中声明「剪切板」用途并重走隐私审核。

**最终采用 A**：不触碰隐私接口，不受业务域名限制。

### 3.2 二维码：离线生成 + 端到端验证

| 项 | 说明 |
|---|---|
| 生成脚本 | `scripts/gen-quiz-qr.js`（可重复运行） |
| 依赖 | `qrcode`（**仅生成时使用**，装在隔离工作区；小程序运行时**零依赖**） |
| 输出 | `miniprogram/images/qr/*.png`（10 张，共 **22.3 KB**） |
| 清单 | `scripts/qr-manifest.json`（**刻意放在 miniprogram 外**，避免被打包） |
| 参数 | 320×320、纠错级 M、margin 1、深色 `#2c2c2a` / 浅色 `#ffffff` |

**⚠️ 为何不用第三方二维码 API**：当日实测已确认 `advanced-personality.com` 被 **DNS 层阻断**（公共 DNS 返回 `0.0.0.0`）。依赖外部二维码服务同样是单点故障，故选择离线生成后打包。

### 3.5 新 quiz 页实现要点

```
pages/quiz/quiz.js    分组链接数据（含 name/note/url/qr）+ previewQr() + onShareAppMessage()
pages/quiz/quiz.wxml  分组渲染；每项左文右码；<image show-menu-by-longpress="{{true}}">
pages/quiz/quiz.wxss  沿用既有设计令牌（#efe4cf 底 / #9b2f25 主色 / #fffaf0 卡片）
```

**🔑 关键属性**：`show-menu-by-longpress="{{true}}"` —— **没有它，长按不会出现「识别图中二维码」**，整个方案就失效。
**交互**：卡片整体可点 → `wx.previewImage` 全屏放大二维码（`wx.previewImage` **非**隐私接口），便于长按识别。
