# 向晚问思 · 阶段一 手把手部署云函数（小白版）

> 目标：把你（和我）写好的 5 个「后端小程序」上传到微信云，让真机微信能真正调大模型。
> 之前 `chat` 部署报 `ResourceInUse.FunctionName`，多半是**环境选错 / 开发者工具缓存**。本指南用命令行（CloudBase CLI）绕开这个坑，一步一步跟着做就行。

---

## 第 0 步：先确认你电脑装了 Node.js（没有就装）

1. 打开命令行：
   - Windows：按 `Win` 键，输入 `PowerShell`，点「Windows PowerShell」打开。
   - （如果你习惯用 Git Bash 也行，命令一样。）
2. 在黑窗口里输入：
   ```
   node -v
   ```
   按回车。
3. 如果显示类似 `v18.x.x` / `v20.x.x` / `v22.x.x` → **已装好，跳到第 1 步**。
4. 如果显示「不是内部或外部命令」→ 去 https://nodejs.org 下载 **LTS 版** 安装（一路下一步），装完**重开命令行**再试 `node -v`。

---

## 第 1 步：打开微信开发者工具，进到你的项目

- 双击桌面「微信开发者工具」。
- 在列表里找到「向晚问思」项目，点它打开。
- 能看到左边有代码、右边有手机预览，就算打开成功。

---

## 第 2 步：选 / 确认云环境（**这一步最关键，之前报错多半是它**）

1. 在开发者工具**左上角或左侧**，找「**云开发**」按钮，点它（第一次会让你「开通」，按提示开通一个环境，随便起名，比如 `wendao`）。
2. 开通后，看窗口**顶部有一行「环境：xxx」的下拉框**。
3. 确认下拉框里**已经选中了一个环境**（不是空白、不是「未选择」）。
4. 记住这个环境的**名字**（比如 `wendao-env-1`），下一步要找它的 ID。

> ⚠️ 重点：接下来所有命令里的「环境 ID」必须和这里选中的是**同一个**。选错环境 = 又会出现 `ResourceInUse` 同名冲突。

---

## 第 3 步：复制环境 ID（一串字母数字）

**方法 A（开发者工具里）**：
- 在云开发面板，点左侧「**概览**」或「**设置**」。
- 找「**环境 ID**」那一栏，右边有个「复制」按钮，点它。
- 得到类似 `cloud1-7gxxx1234abc` 这一串，先粘贴到**记事本**里存着。

**方法 B（网页版，更稳）**：
- 浏览器打开 https://console.cloud.tencent.com/tcb → 登录你的微信账号。
- 左上角切到你的环境 → 概览页复制「环境 ID」。

> 把这一串环境 ID 整段复制好，下面每一步都要用。**别手打**，容易错。

---

## 第 4 步：打开命令行（专门用来敲部署命令）

- 回到 PowerShell / Git Bash 黑窗口（就是第 0 步那个）。

---

## 第 5 步：安装 CloudBase 命令行工具（只需装一次）

在黑窗口输入：
```
npm install -g @cloudbase/cli
```
按回车，等它跑完（可能要几十秒，出现进度条正常）。

装完验证：
```
tcb -v
```
显示版本号（如 `2.x.x`）= 装好了。
如果显示「tcb 不是命令」→ 关掉黑窗口重开再试；还不行就是 Node 没装对，回第 0 步。

---

## 第 6 步：登录（扫码）

在黑窗口输入：
```
tcb login
```
按回车 → 它会弹出**浏览器**，用微信扫码登录（扫你注册小程序的那个微信）→ 点「确认」→ 黑窗口显示「登录成功」。

---

## 第 7 步：逐个部署 5 个云函数（核心动作）

> 这 5 个是：`login` `history` `chat` `feedback` `admin`
> **其中 `chat` 必须部署**——我们刚把它内存从 256 调到 512，不重传不生效。

### 7.1 先进入云函数文件夹

在黑窗口输入（**这是你电脑上的真实路径，照抄**）：
```
cd "D:\不知道是啥\教员\weapp\cloudfunctions"
```
按回车。
> 如果报错「系统找不到指定的路径」→ 说明你项目不在 D 盘这个位置。去文件管理器找到 `weapp/cloudfunctions` 文件夹，按住 Shift 右键它 → 「复制文件地址」，把 cd 后面引号里的内容换成你复制的地址。

### 7.2 一条一条部署（每条都要做）

把下面**每一行**单独复制到黑窗口、按回车。注意把 `你的环境ID` 换成第 3 步复制的那串：

```
tcb fn deploy login --envId 你的环境ID
```
等到显示「部署成功 / deploy success」→ 再发下一条：
```
tcb fn deploy history --envId 你的环境ID
```
```
tcb fn deploy chat --envId 你的环境ID
```
```
tcb fn deploy feedback --envId 你的环境ID
```
```
tcb fn deploy admin --envId 你的环境ID
```

> ✅ 正常结果：每条最后都出现绿色「部署成功」字样。
> ❌ 如果某条报 `ResourceInUse` → **环境 ID 填错了**，回去第 2、3 步确认选中的环境，重新复制 ID 重跑那条。
> ❌ 如果报「找不到函数目录」→ cd 路径不对，回 7.1。

**懒人法（一条发完 5 个）**：也可以一次性粘贴这段（同样替换环境 ID）：
```
for f in login history chat feedback admin; do tcb fn deploy $f --envId 你的环境ID; done
```

---

## 第 8 步：确认部署成功

1. 回到**微信开发者工具**的云开发面板 → 左侧「**云函数**」。
2. 看列表里有没有这 5 个：`login` `history` `chat` `feedback` `admin`。
3. 看它们「**更新时间**」是不是**今天**（证明刚传上去）。
4. 点 `chat` → 点「**日志**」标签 → 随便在小程序里发一问 → 回来刷新，看有没有**新日志**进来。
   - 有日志 = 部署通了，函数能跑。
   - 没日志 = 没部署成功，回头看第 7 步报错。

---

## 第 9 步：告诉 AI 你做到哪了

做完上面，给 AI 发一句：
- 「5 个函数都部署成功了」→ 我带你去阶段二（配模型）。
- 或把**报错截图**发我 → 我帮你定位。

## 常见问题速查

| 现象 | 原因 | 解决 |
|---|---|---|
| `ResourceInUse.FunctionName` | 环境 ID 和开发者工具选中的不一致 | 回第 2/3 步，复制**当前选中环境**的 ID 重跑 |
| `tcb 不是内部或外部命令` | npm 全局没生效 / 没重开窗口 | 关窗口重开；或重装 `@cloudbase/cli` |
| 部署卡住不动 | 网络慢 / 依赖安装中 | 等 1–2 分钟；还不动按 `Ctrl+C` 重跑那条 |
| 日志里没新记录 | 函数没部署成功 / 环境选错 | 确认第 8 步 5 个函数更新时间是今天 |
| 提示「未开通云开发」 | 第 2 步没开通 | 点「云开发」按钮按提示开通环境 |
