### 阶段二：模型配置（决定真机能否调大模型）

> 集合存在 ≠ 模型能调。`model_config` 里**必须有一条 `enabled:true` 且 `apiKey` 非空的记录**，否则 `chat` 静默 fallback 到本地回答（表现：能答但不智能，下方灰字提示"模型未生效"）。

- [ ] **Step 4 · 添加并启用模型记录**
  进入小程序「关于」页 → 底部「对话管理」→「模型配置」→ 新增一条，按下面字段填：

  | 字段 | 填法（以 api.hcnsec.cn 代理为例） | 说明 |
  |---|---|---|
  | `name` | 自定义，如 `hcnsec-deepseek` | 展示用 |
  | `baseURL` | `https://api.hcnsec.cn/v1` | 代码会自动补 `/chat/completions`，**不要**在末尾加 `/chat/completions` |
  | `model` | `DeepSeek-V4-Flash` | 代理支持的模型 ID（Pro 版太慢，作兜底） |
  | `apiKey` | 你的代理 API Key | **必填**，非空 |
  | `timeout` | `30000`（偏慢可填 `60000`） | 单位毫秒 |
  | `enabled` | ✅ 开启 | **必开** |

  > 代码读取逻辑：只取 `where({enabled:true})` 且 `apiKey` 非空的记录（见 `chat/index.js:13-21`）。

- [ ] **Step 5 · 用「测试」按钮验证连通性**
  在模型配置列表点该记录的「测试」按钮（调用 `admin` 云函数 `model_test`）：
  - ✅ 连接成功 → 配置正确，直接进入阶段四
  - ❌ 失败 → 看报错，对照下表：

  | 报错关键字 | 原因 | 解决 |
  |---|---|---|
  | `HTTP_404` / `Model not exist` | 模型 ID 错 | 用代理要求的小写 ID，如 `DeepSeek-V4-Flash`，不要填控制台展示名 |
  | `HTTP_401` / `Incorrect API key` | Key 错或失效 | 换当前有效的 Key |
  | `HTTP_429` / `quota` | 额度/频率超限 | 检查余额或换模型 |
  | `timeout` | 网络/地域/超时 | 把 `timeout` 调到 60000，检查 baseURL 是否正确 |

### 阶段三：安全与权限

- [ ] **Step 6 · 设置 `ADMIN_OPENID`（安全缺口，必须做）**

### 阶段四：真机冒烟 + 433 排查

- [ ] **Step 8 · 前端刷新编译**
  1. 开发者工具文件面板 → 右键 → 刷新（解决之前 `sessions.wxml not found` 的缓存）
  2. 点「编译」
  3. 真机预览/体验版**重新生成二维码**；微信里删掉旧小程序缓存（长按 → 删除）再扫新码

- [ ] **Step 9 · 真机发问 + 看日志**
  1. 真机提一个问题 → 正常应返回带"经典引用 + 解读"的回答
  2. 网页云开发控制台 → 云函数 `chat` → 日志：
     - 应有新日志，且**无红色「调用失败 (433)」**
     - 若回答下方灰字仍提示"模型未生效"，回到 Step 4–5 复查 `model_config`

- [ ] **Step 10 · 若仍出现 433（重点排查）**
  433 = 函数进程被运行环境 kill（不是模型报错，模型错误会被 catch 后 fallback）。
  1. 点开红色「调用失败 (433)」日志 → 展开看 **ERROR / 堆栈**
  2. 把 ERROR 文字发给我，定位真因。常见方向：
     - 含 `memory` / `killed` / `OOM` → 内存不足（已把 `chat` 提到 512MB，必要时再升 1024MB）
     - 含 `msgSecCheck` / `openapi` → 内容安全权限未开通（回 Step 7）
     - 含具体某行报错 → 针对性修代码
  > 注：之前误判 `corpus.json` 7.6MB 导致 OOM，实际仅 7.6KB，该诊断已撤销；`chat` 内存已提到 512MB（无害余量）。433 真实根因须看日志。
