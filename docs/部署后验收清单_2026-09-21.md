## P0-1 · 【最高优先】验证环境变量未被改坏

**只在一种情况下需要高度警惕**：如果你用的是 **CLI 的 `tcb fn deploy`**（含 `--all`）。

原因：`tcb fn deploy` 会套用 `cloudbaserc.json` 的 `envVariables`，而该文件**当前与生产不同步**：

```
cloudbaserc.json 里写的是:  "SEARCH_PROVIDER": "agnes"
生产实际应为:               "qwen"
```

→ 一旦套用，`SEARCH_PROVIDER` 被静默改回 `agnes`，而 **agnes 是纯 LLM 代理、不返实时联网数据** → 联网失效，复发 2026-08-08 刚修好的「用户感知不能联网」缺陷。

> 若你用的是**微信开发者工具**上传，则不会套用 `cloudbaserc.json`，此风险不存在 —— 但仍建议核一眼。

**验证方式（择一即可）**

| 方式 | 操作 |
|---|---|
| A. 控制台查看 | 云函数 → `chat` → 「版本与配置」→ 环境变量 → 确认 `SEARCH_PROVIDER` = **`qwen`** |
| B. 行为验证 | 小程序问一个**必须实时联网**的问题（例：「最近有什么科技新闻？」），看是否返回真实时效性信息；若回答泛泛而谈、无具体事件 → 疑似已回退 agnes |

**结果**：☐ 正常（qwen） ☐ 异常（agnes） ☐ 未验证
