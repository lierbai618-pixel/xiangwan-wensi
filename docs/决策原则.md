# 决策原则（Decision Principles）

> 当需求、点子、PR 涌进来时，按以下顺序判断。任一步为"否"，就不做。

## 需求五问过滤器

```
① 是否符合产品定位？（哲学思辨助手，帮人思考而非给答案）
      ↓ 否 → 不做
② 是否帮助用户思考？（拓展视角 / 理解自己 / 做自己的判断）
      ↓ 否 → 不做
③ 是否增加维护成本？（是否让系统更复杂、更难运维）
      ↓ 是 → 谨慎 / 推迟
④ 是否影响 RAG？（是否改动检索 / 知识库核心）
      ↓ 是 → 必须同步更新 docs/ 与验收标准
⑤ 是否属于 MVP？（当前阶段是否必要）
      ↓ 否 → 记入路线图，不现在做
```

## 开发纪律（写进项目）

1. 一次只完成一个 Phase。
2. 未通过评审，不进入下一阶段。
3. 不得跨 Phase 提前开发。
4. 不得删除旧模块，**只允许冻结归档**（移入 `archive/`）。
5. **【项目第一原则】任何影响产品定位、产品边界、回答规范、知识库的修改，必须先更新 `docs/`，再修改代码。** 此条优先级高于一切开发便利；代码与文档冲突时以 `docs/` 为准。
6. 所有新增功能必须对应更新文档与验收标准。
7. 文档与代码冲突时，以 `docs/` 为准，并立即修代码或修文档。

> **项目第一原则**：以上第 5 条（先改 `docs/` 再改代码）是整个项目的第一原则，优先级高于一切开发便利。任何 Prompt、RAG、首页、知识库的变动，都先落到文档，再落到代码。
