## 二、Step 3 百问验证：记录口径（不只测正确率）

每收到一个真实问题，就在 `phase-f-100-test.json` 的 `records` 里填一行：

| 字段 | 含义 | 填法 |
|---|---|---|
| `id` | 序号 | 1..100 |
| `question` | 用户真实提问原文 | 原样记录，不改写 |
| `theme` | 人工归类主题 | 迷茫 / 学习 / 行动 / 关系 / 自我 / 其他 |
| `mode` | 回答模式 | plain / deep / classic |
| `expected_books` | 预期可能命中的经典 | 人工预判（如《论语》《沉思录》） |
| `actual_books` | 实际命中经典 | 取回答里 `route.books` 的值 |
| `citation_correct` | 引用是否准确 | 布尔：经典是否真的支撑了该观点 |
| `useful` | 用户是否觉得有帮助 | 布尔：以 👍/👎 与追问判断 |
| `notes` | 观察备注 | 用户语言变化、二次追问内容、卡点 |

### 五类分布（保持均衡）
人生方向 20 / 学习成长 20 / 情绪压力 20 / 关系问题 20 / 长期选择 20

### 比"正确率"更重要的三个信号
1. **二次追问率**：用户收到回答后是否继续追问（"那我具体该怎么做？"）——说明回答激发了思考。
2. **引用展开率**：用户是否点击"查看思想来源"——说明引用体系有效（当前未埋点，靠人工观察）。
3. **用户语言变化**：从"人生没意义"到"我是不是该先调整行动"——产品真正产生影响（定性人工读时间序）。

## 五、回答完整性检查（v0.9.3-hotfix 引入）

> 背景：v0.9.3-hotfix 之前，`weapp/cloudfunctions/chat/rag.js` 的 `max_tokens: 400` 硬截断导致五段回答经常缺失【思考】段与【经典】最后一条 AI 解读。修复后（commit `8bdfa6e`，tag `v0.9.3-hotfix`）将上限提到 2000 tokens。**从此每条真实问题都要记录"是否完整"，否则 100 问数据的"回答满意度"维度不可信。**

### 5.1 必填字段

在 `weapp/phase-f-100-test.json` 的 `records` 里每条新增两个字段：

| 字段 | 类型 | 含义 | 填法 |
|---|---|---|---|
| `answer_complete` | `bool \| null` | 是否完整输出五段结构 | `true`=全 5 段齐 / `false`=缺段 / `null`=未测 |
| `finish_reason` | `string \| null` | 模型生成结束原因 | `stop`=完整收尾 / `length`=被截断 / `content_filter`=安全拦截 / `null`=未测 |

### 5.2 五段结构判定

完整五段 = 同时存在以下 5 个段标：

```
【理解】 → 【分析】 → 【行动】 → 【经典】 → 【思考】
```

只要任何一个缺失 → `answer_complete = false`（即使模型 `finish_reason=stop`，也要人工核查段标是否真在；某些情况下模型跳过段标直接写内容）。

### 5.3 截断判定（endsTrunc 启发）

回答**不以"问号/句号/感叹号/右引号"结尾**的，疑似被截断 → 优先看 `finish_reason`：

| `finish_reason` | 含义 | 处理 |
|---|---|---|
| `stop` | 模型自然收尾 | 理论上完整，再人工核段标 |
| `length` | 达到 max_tokens 上限 | 截断 → `answer_complete=false` + notes 记"截断于XXX段" |
| `content_filter` | msgSecCheck 安全拦截 | 视为不安全，notes 记具体拦截内容关键词 |
| `null` 或其他 | 未测 / 未知 | notes 记"未观察到 finish_reason 字段" |

### 5.4 与其他字段的关联

- `answer_complete=false` 的记录应在 notes 标"❌截断"，便于统计"截断率"
- `finish_reason=length` 的记录应反查云函数部署版本（v0.9.3-hotfix 之前/之后）
- 截断率 > 10% 的批次需要排查是否 max_tokens 改回 400 或新部署未生效

### 5.5 100 问数据完整性指标

- **完整率**：`answer_complete=true` 的记录数 / 总测试数 ≥ **95%**（目标）
- **截断率**：`finish_reason=length` 的记录数 / 总测试数 ≤ **5%**
- **典型截断位置**：notes 应标"截断于【X】段"，便于后续按段统计

### 5.6 验证脚本（参考）

