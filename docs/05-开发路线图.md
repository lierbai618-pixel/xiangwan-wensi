# 05 开发路线图

> 纪律：**一次只完成一个 Phase；未通过评审不进下一阶段；不得跨 Phase 提前开发；不得删除旧模块，只允许冻结归档。**

## Phase A — 产品宪法（当前）

- **输入**：产品定位确认
- **输出**：`docs/` 全部文档（本目录）
- **验收**：文档体系完整，成为 SSOT（唯一事实来源）

## Phase B — Prompt 重构

- **输入**：产品定义 + AI 回答规范
- **输出**：`rag.js` 新 `rolePrompt`（结构化 `ROLE_PROMPT`：System / Identity / Mission / Workflow / Safety / Output Contract；由 `buildRolePrompt()` 组装为 system 文本）
- **验收**：回答符合思辨风格，不站队、不输出唯一答案

## Phase C — 知识库 MVP

### Phase C-1 — 知识资产结构设计（本回合）

- **输入**：`03-知识库规范.md` + 公有领域/授权清单
- **输出**：`knowledge/` 资料仓目录树 + 每本书 `metadata.json` 规范 + `07-知识资产结构.md` 接入规范 + 首批清单（10~15 本）+ 入库验收标准
- **验收**：结构冻结、规范可 machine-read、首批清单含版权状态、不批量 ingest

### Phase C-2 — 资料接入与入库（待 C-1 评审通过后）

- **输入**：`knowledge/` 中 `status: ready` 的资料包 + 扩展后的 `ingest`
- **输出**：`documents` / `chunks` 集合填充（带 `perspective` / `themes` 字段）
- **验收**：首批经典成功入库，引用 `source_position` 可追溯到具体章节与字符区间；`corpus.json` 旧语料冻结归档

## Phase D — MVP 产品体验

- **输入**：新 Prompt + 新知识库 + UI 规范
- **输出**：首页（话题 + 每日思考）、聊天页（框架切换 + 引用卡片）
- **验收**：见 `01-产品定义.md` 第 11 节（量化验收：≥1 引用、≥2 视角、原文/解读分离、≥1 开放问题、无唯一答案、引用可追溯）

## Phase E — RAG 升级

- **输入**：Phase D 稳定
- **输出**：意图识别 + 按 category / author / keywords 多库融合
- **验收**：不同主题问题能正确路由到对应知识源

## Phase F — 内容运营

- **输入**：MVP 上线
- **输出**：每日思考、每周专题、阅读路线
- **验收**：形成可持续的内容供给能力

## 里程碑总表

| 阶段 | 目标 | 验收标准 |
|---|---|---|
| A | 产品宪法 | 文档完成，SSOT 建立 |
| B | Prompt | 新 Prompt 生效，符合思辨风格 |
| C | 知识库 | 首批经典入库，可正确引用 |
| D | MVP | 首页 / 聊天 / 引用 / 每日思考可用 |
| E | RAG | 意图识别 + 多库融合完成 |
| F | 产品化 | 专题 / 路线 / 运营能力完善 |
