## 二、移除 `outputContract` 的依据（已实测确认）

原判断为「全仓无引用」，**但该判断不准确** —— `scripts/test_phaseb_prompt.js` 确实读取了它。进一步核查生产消费路径：

| 消费点 | 实际取用的键 | 是否含 `outputContract` |
|---|---|---|
| `rag.js → buildRolePrompt()`（第 431–441 行） | `system / identity / mission / workflow / safety` + **`fmt.contract`** + `lengthHint` + 模式指令 | ❌ **不含** |
| `freshness/responder.js`（第 238–241 行） | `system / identity / mission / safety` | ❌ **不含** |

**结论**：生产 prompt 的输出结构完全由 **`OUTPUT_FORMATS[*].contract`**（经 `resolveFormat()`）决定，`outputContract` **不参与组装**。

**但注释声称它"等价于 OUTPUT_FORMATS.general"，且内部残留一个已废弃的【建议】** → 保留会持续误导维护者以为它仍生效。故移除。

**顺带发现（既有问题，非本轮引入）**：`scripts/test_phaseb_prompt.js` 在本轮改动前即为 **16 通过 / 6 失败**。它断言的是旧版 prompt 措辞（"思辨助手"、"陪用户一起思考"、六步 workflow），而 prompt 早已重写为「通用助手 + 经典增强」。

| 失败断言 | 性质 |
|---|---|
| 组装文本含 identity | 既有 · 措辞漂移 |
| 组装文本含 mission | 既有 · 措辞漂移 |
| 组装文本含 workflow 六步 | 既有 · 措辞漂移 |
| 组装文本含 outputContract 结构 | **既有**（该断言自始不成立，`buildRolePrompt` 从不消费 outputContract）→ **本轮修正** |
| 原文/解读分离 | 既有 · 措辞漂移（现措辞为「严格区分『经典原文』与『你的解读』」） |
| 无唯一答案 | 既有 · 措辞漂移 |

→ 本轮只修正了与 `outputContract` 直接相关的那 1 条，**其余 5 条刻意未动**（属另一个议题：该测试是否应更新或退役，宜单独处理，不应夹带在本 CR 中）。

**本次改动与该产品线相关**，建议后续一并审视两者的分工，避免"情绪支持"在两个入口给出形态不一致的回应。
