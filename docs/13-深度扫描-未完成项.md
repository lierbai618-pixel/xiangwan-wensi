## 🔴 阻断性 Bug（建议立即修，均在冻结允许的"修阻断性 bug"范围内）

### 1. 管理页三块洞察永不渲染（最严重，破坏 Phase F 数据闭环可见性）
- **现象**：admin 页"百问分类进度 / 回答有帮助率 / 为什么有效无效"三块始终空白。
- **根因**：`admin.js` 的 `loadInsights`（约 `admin.js:90-95`）只 `setData` 了 `totalQuestions / topTags / topQuestions`；
  但云函数 `admin/index.js` 的 `insights` 实际返回了 `categoryBreakdown / feedback / quality`（`admin/index.js:374-376`）。前端把这三个字段整段丢弃。
- **铁证**：`admin.wxml` 在 `:113 / :123 / :135` 明确引用 `insights.categoryBreakdown` / `insights.feedback` / `insights.quality`，却永远拿不到数据 → 区块 `wx:if` 不满足，不渲染。
- **影响**：这正是 Phase F「百问验证」要观察的核心指标（五类进度 / 有帮助率 / 定性原因）。不修，admin 看板等于瞎的，100 问数据无法按设计复盘。
- **修复（一行级）**：`loadInsights` 的 `setData` 补三项：
  `categoryBreakdown: r.categoryBreakdown || [], feedback: r.feedback || {}, quality: r.quality || {}`。
- **冻结纪律**：仅补前端数据回填，不改回答结构 / 标签 / feedback 文案 / prompt 比例。✅

### 2. 关于页「意见反馈」必然失败
- **现象**：在"说明"页点意见反馈，任意内容都返回"提交失败"。
- **根因**：`about.js:64` 调用 `feedback` 时传 `data: { text }`；但 `feedback/index.js:13` 只读 `data.question` → `question` 为空 → `:16-18` 直接 `return { ok:false, error:"缺少问题内容" }`。
- **铁证**：聊天页 `chat.js:281-295` 的 `submitFeedback` 传的是 `question` 字段（正常）；只有关于页用了错的 `text` 字段。
- **修复（一行级）**：`about.js:64` 改 `data: { question: text }`（对齐聊天页）。
- **冻结纪律**：仅修正字段名，未改 feedback 文案/行为。✅
