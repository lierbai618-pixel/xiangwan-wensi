## 三、⚠️ 连带后果（必须知情）

### 3.1 `quality` 块现在变成**永不渲染的死 UI**

删除反馈卡片后，`_feedback` **再无任何代码路径会赋值**（`rateAnswer` / `chooseReason` 已失去绑定）。而紧随其后的 `quality` 块条件为：

```html
<view wx:if="{{item.role === 'assistant' && item._isAnswer
               && item._feedback != null && !item._showReasons}}" class="quality">
```

`item._feedback != null` 恒为假 → **该块永不显示**。

它承载的是 **Phase F · `answer_quality_log`** 的可选定性补充（"这条回答哪里帮到你 / 没帮到你？"），文件注释明确标为"不打断主流程"。

### 3.2 数据追踪链的入口被切断

```
question_logs → answer_id → answer_feedback → answer_quality_log
                              ↑ 入口在此
```

| 影响 | 说明 |
|---|---|
| `answer_feedback` 集合 | **不再产生新数据** |
| `answer_quality_log` 集合 | **不再产生新数据** |
| `feedback` 云函数 | **失去唯一调用方**（`chat.js:545`、`:592` 两处调用点均已不可达） |
| 历史数据 | **不受影响**，已入库的反馈记录完整保留 |

> 这是本次改动**最需要你确认的后果**。若本意只是"不想在界面上看到它"，那前端不渲染即可；但这同时意味着**放弃了该链路的增量数据采集**。

### 3.3 孤儿清单（均为刻意保留，非疏漏）

| 类型 | 对象 |
|---|---|
| 孤儿方法 | `rateAnswer` / `chooseReason` / `submitFeedback` / `toggleQuality` / `onQualityInput` / `submitQuality`（后三者随 `quality` 块失效） |
| 孤儿样式 | `chat.wxss` 中约 19 条 `.route*` / `.fb-*` / `.feedback` / `.quality` 规则 |
| 孤儿字段 | 消息对象的 `_feedback` / `_showReasons` / `_qualityOpen` / `_qualityDone` 等 |

保留理由：**回滚成本最低**（恢复 wxml 即恢复功能）。代价是短期存在死代码。
